梯子安全吗？一句话回答不了，因为风险分在三个不同的层面：传输层（数据在路上被谁看到）、账号层（你交给服务商的信息）、软件来源层（你装的客户端可不可信）。技术上，访问 HTTPS 网站时机场只能看到域名、流量大小这类元数据，看不到加密的内容。但现实里更常见的风险，往往出在假官网、订阅泄露和来路不明的软件上。

## 梯子安全吗：先把风险分成三层

很多关于梯子安全吗的讨论混在一起，答案才会互相矛盾。分层后就清楚了：

| 层 | 在担心什么 | 主要风险点 | 你能做什么 |
| --- | --- | --- | --- |
| 传输层 | 机场或线路上的人能看到什么 | 明文网页、不安全的 DNS、不明证书 | 优先使用 HTTPS，检查 DNS，不装陌生证书 |
| 账号层 | 你交给服务商的信息安全吗 | 邮箱、支付信息、订阅链接泄露，假官网 | 独立邮箱和密码，核实官网，保护订阅 |
| 软件来源层 | 装在设备上的客户端可信吗 | 破解版、整合包、被修改的安装包 | 只从官方发布页和应用商店获取 |

一个常见误解是把“梯子加密了流量”理解成“梯子很安全”。加密只保护了传输的一小段，账号和软件层的问题，加密解决不了。反过来，也不必因为机场“技术上能看到一些东西”就认为梯子很危险，关键是知道它能看到什么、看不到什么。

## 机场能看到什么、看不到什么

你的流量经过节点，节点一端是你，另一端是目标网站，它处在中间位置。下表是机场视角下的信息清单：

| 信息 | 机场能否看到 | 说明 |
| --- | --- | --- |
| 你访问的目标域名 | 能 | 客户端要告诉节点去哪，或握手信息里带有域名 |
| 目标服务器的 IP | 能 | 节点要替你连接，必然知道 |
| 流量大小、时间、频率 | 能 | 这是计费和限流需要的基础数据 |
| 你的真实出口 IP | 能 | 连接是从你的网络发来的 |
| HTTPS 网页的具体内容、账号密码 | 看不到 | 内容在你和网站之间端到端加密 |
| 没有加密的 HTTP 网页内容 | 能看到，也可能被改动 | 明文传输，没有任何保护 |
| 加密聊天软件的消息内容 | 看不到 | 取决于软件自身的加密 |
| 设备上的文件、通讯录 | 看不到 | 正规客户端不会上传，来路不明的软件另当别论 |

按这张表，机场更像一个“能看到你去过哪些地方、去了多久，但看不到你在里面说了什么”的中转站。这对多数用途是可以接受的，但如果你的访问记录本身就敏感，就要把“机场能看到域名”当作前提来考虑。

换个角度，把链路上几方各自能看到的内容放在一起：

| 谁 | 能看到 | 看不到 |
| --- | --- | --- |
| 你所在的宽带或移动网络 | 你连着某台代理服务器，以及流量的大小和时间 | 隧道里的具体访问内容，前提是协议本身加密 |
| 机场的节点 | 目标域名和 IP、流量、时间、你的出口 IP | HTTPS 的加密内容 |
| 目标网站 | 来访 IP 是节点的 IP，以及你登录后的账号行为 | 你的真实 IP，除非另有泄露 |
| 客户端的开发者 | 取决于软件本身，正规开源项目的代码可公开审查 | 一般不应读取与代理无关的数据 |

注意第三行：目标网站看到的是节点的 IP，并不意味着你匿名。你一旦登录账号，网站认识的就是这个账号，换出口 IP 也不会改变这一点。

还有一类信息取决于设置：DNS 查询。如果客户端没有把域名解析也交给代理，解析请求可能从本地发出，造成泄漏。检测和修复方法见[DNS 泄漏怎么查](/paicha/dns-xielou/)，DNS 本身是什么可以读 [Cloudflare 的 What is DNS](https://www.cloudflare.com/learning/dns/what-is-dns/)。

## 为什么 HTTPS 内容看不到：两句话讲原理

以 HTTP 代理为例，访问 HTTPS 网站时，客户端会先请求代理建立一条通往目标的隧道，之后浏览器和网站之间的加密握手和数据，都是在这条隧道里直接完成的，代理只负责转发，见 [Mozilla MDN 对代理与隧道的说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Proxy_servers_and_tunneling)。其他代理协议的细节不同，但“转发加密数据”这一点相似。

这个结论有一个**重要前提**：你的设备没有信任节点方给你的证书。如果某个节点或客户端要求你安装根证书，等于授权它替你“拆封”加密的流量，那它就能看到 HTTPS 内容了。所以牢记一条规则：**任何要求你安装根证书的梯子服务，都不要接受**。

另一个常见问题是协议本身的加密。你和节点之间这一段用的什么协议、加密强度如何，由协议和客户端决定，可以参考[机场协议怎么选](/zhinan/jichang-xieyi/)。至于梯子和 VPN 在原理上的差别，见[梯子和 VPN 的区别](/zhinan/tizi-he-vpn/)。

## 账号和软件层面的风险，比传输更常见

真正导致损失的，更多是下面这些。

- **假官网。** 钓鱼站仿冒机场页面，骗取账号、支付信息。识别方法见[机场假官网怎么识别](/bikeng/jia-guanwang/)。
- **订阅链接泄露。** 订阅等于账号，泄露后别人能消耗你的流量，补救办法见[订阅链接泄露了怎么办](/bikeng/dingyue-xielou/)。
- **破解版和修改版客户端。** 这类软件可能被植入额外代码，是最危险的一类，详细风险见[破解版梯子软件](/bikeng/pojie-kehuduan/)。
- **免费节点和免费应用。** 来源不明，责任不清，见[免费梯子](/zhinan/mianfei-tizi/)。
- **密码复用。** 机场账号用了和邮箱、支付账号相同的密码，一处泄露，处处遭殃。
- **服务商本身出问题。** 跑路、被攻击、数据泄露，用户资料可能因此外泄。

合规方面，只提一句：请遵守所在地法律法规，选梯子不提供法律意见。

## 机场会记录什么：隐私政策里该看哪几句

“无日志”几乎是所有机场的宣传语，但它是自我声明，外部无法验证。判断一家机场的隐私态度，更实际的是读它的隐私政策，看这几件事：

1. **记录哪些信息。** 只记流量用量，还是记录访问的域名、连接时间、来源 IP。
2. **保存多久。** 有没有明确的保存期限，有没有说到期删除。
3. **是否提供给第三方。** 在什么情况下会向他人披露。
4. **运营主体是谁。** 写不清运营主体的，出了问题连找谁都不知道。
5. **有没有隐私政策。** 压根没有这个页面，本身就是一个信号。

具体怎么读，见[机场会记录日志吗](/bikeng/jichang-rizhi-yinsi/)。即使政策写得好，也要明白它只是服务商的承诺，不是技术层面的约束。重要的操作，不要把安全全部寄托在“无日志”三个字上。

## 降低梯子风险的六个习惯

下面六条不需要技术背景，坚持做就能大幅降低风险：

1. **机场账号单独用一个邮箱和一个密码。** 不与银行、支付、工作邮箱重复。
2. **只通过收藏的官网地址登录。** 不从搜索广告、聊天群里的链接进入。
3. **订阅链接当密码一样保管。** 不发给别人，不贴到公开页面，怀疑泄露就重置。
4. **客户端只从官方仓库或应用商店获取。** 不装整合包、破解版、网盘里的安装包。
5. **不安装任何陌生证书。** 无论谁要求，包括看起来有来头的节点或客户端。
6. **重要的账号只在 HTTPS 页面输入。** 看到网址不是 https 开头，或浏览器提示不安全，不要输入密码。

另外，付款时少留信息，注册用独立邮箱，必要时把重要账号开启两步验证，都是低成本的保护。

## 怎么自己核对：六项检查

不要只听“安全”或“不安全”的结论，自己做一遍检查：

1. **看网址和连接标识。** 访问重要网站时，确认是 https，浏览器地址栏的连接状态正常，具体样式随浏览器版本变化。
2. **做一次 DNS 泄漏检测。** 方法见[DNS 泄漏怎么查](/paicha/dns-xielou/)，确认解析请求没有绕开代理。
3. **检查系统里有没有陌生根证书。** 在系统的证书管理界面查看，看到来路不明、与你无关的证书，应当移除，并查明是谁装的。
4. **核对客户端来源。** 回到官方发布页，对照项目名和作者，确认安装包来自哪里。
5. **读一遍隐私政策和退款条款。** 把记录什么、保存多久、运营主体三项摘出来。
6. **确认订阅可以重置。** 在机场后台找到重置订阅的入口，确认出问题时你有办法让旧链接失效。

如果前三项中有任何一项异常，先暂停使用并排查；后三项不通过，说明这家服务商的透明度不足，值得重新考虑。
