Telegram 一直连接中，而梯子已连接、网页也能打开，问题通常不在线路，而在 Telegram 这个程序没有走到代理上。它可能不读取系统代理，可能留着一条失效的旧代理，也可能因为规则没有覆盖它的服务器地址而被直连。下面按状态文字、应用内代理、本地端口、规则和对照实验的顺序逐项排查。

## 顶部那行字说明什么：Telegram 一直连接中的几种状态

不要只看“连不上”三个字，顶部的状态文字本身就是线索。不同版本的措辞略有差异，以当前界面为准。

| 顶部显示 | 说明什么 | 下一步 |
| --- | --- | --- |
| 连接中（Connecting） | 应用在尝试直接连服务器，但没有连通 | 做第二步、第三步 |
| 正在连接代理（Connecting to proxy） | 应用里配置了代理，它在尝试这条代理 | 做第一步，检查代理是否失效 |
| 更新中（Updating）长时间不消失 | 连接勉强建立，但数据同步被卡住 | 做第四步，对照换节点 |
| 等待网络（Waiting for network） | 应用认为设备当前没有可用网络 | 检查设备网络，确认 VPN 真的在运行 |
| 网页版 Telegram 能开，App 连不上 | 网页走浏览器，App 有自己的网络路径 | 做第二步到第四步 |

后面按由易到难排。每一步只改一处，改完观察顶部状态变化，再决定是否继续。

## 第一步：检查应用内是否残留失效的代理

Telegram 应用内支持设置 SOCKS5 与 MTProto 代理，官方的[代理说明页](https://core.telegram.org/proxy)写明了这一点，并说明代理设置在不同平台上的入口不同。一旦设置了，它会优先通过这条代理连接。代理失效，或者指向的本地端口已经没有程序在监听，就会一直停在连接状态。

入口在应用的设置里，桌面版通常在高级设置的连接类型里，手机版通常在数据与存储里，名称以当前版本为准。

1. 打开代理设置，看列表里有没有以前添加过的代理。
2. 失效的、不认识的，删除，或者关闭“使用代理”的开关。
3. 回到主界面，观察顶部是否很快恢复正常。

顺带提醒：不要添加陌生人分享的公开代理。流量经过对方的服务器，风险和公开订阅类似，见[免费节点的风险](/bikeng/mianfei-jiedian-fengxian/)。

## 第二步：手动填本地 SOCKS5，让 Telegram 走到代理上

Telegram 不一定读取系统代理，所以最直接的办法是在应用里指明代理。这里填的不是机场节点的服务器，而是你本机上代理客户端的监听地址。

1. 在代理客户端里找到本地监听端口，一般叫混合端口或 SOCKS 端口，以你的客户端显示为准。
2. 在 Telegram 的代理设置里添加一个代理，类型选 SOCKS5。
3. 按下面填写：

```
类型：SOCKS5
服务器：127.0.0.1
端口：<你的客户端显示的混合端口或 SOCKS 端口>
用户名、密码：留空（除非你给本地代理设置了认证）
```

4. 保存并启用，观察顶部状态。

混合端口同时支持 HTTP 和 SOCKS5，可以直接使用。如果以后客户端的端口改过了，或者启动时报端口被占用，Telegram 里填的端口也要同步修改，排查方法见[Clash 端口被占用](/paicha/duankou-zhanyong/)。关于 Telegram 的连接与代理说明，可以对照[Telegram 官方 FAQ](https://telegram.org/faq)，页面内容以官方为准。

系统代理和 Telegram 的关系，可以参考[系统代理](/jiaocheng/xitong-daili/)一篇。

## 手机上：VPN 方式、分应用名单与省电策略

手机上的客户端以 VPN 方式运行，会接管整台设备的流量，通常不需要在 Telegram 里再设置代理。手机上 Telegram 连不上，常见的原因是：

1. **客户端没有真正连接**。确认状态栏有 VPN 标志，客户端内显示为已连接。
2. **Telegram 被放在了不走代理的一侧**。客户端若有分应用代理，检查 Telegram 是在代理名单里，还是在绕过名单里。思路见[App 不走代理](/paicha/app-buzou-daili/)。
3. **客户端被系统后台管理停掉了**。在系统设置里允许它在后台运行，关闭针对它的电池优化。
4. **应用内还留着旧代理**。回到第一步检查。

## 第三步：规则没覆盖，Telegram 是按 IP 连接的

规则模式下，只有命中规则的流量才会走代理。多数网站是先解析域名，再按域名判断，但 Telegram 应用通常直接用内置的服务器 IP 地址发起连接。这意味着只写域名规则管不到它，需要有覆盖 Telegram 服务器 IP 段的规则。

怎么确认：

1. 在客户端的连接页里，让 Telegram 重新连接。
2. 找它的连接记录。如果目标只有一个 IP、没有域名，而且链路显示为直连，就是规则没覆盖。

怎么处理：更新订阅自带的规则，或者在规则里启用社区维护的、包含 Telegram 服务器 IP 段的规则集。不要手抄 IP 段，服务器地址会变化，由规则集维护者更新更可靠。规则的组织方式见[Clash 规则模式、全局模式、直连模式](/jiaocheng/guize-quanju-zhilian/)。

## 第四步：用 TUN 和全局模式做对照实验

怀疑规则或应用不读取系统代理时，做两个对照实验，比反复猜测快得多。

| 实验 | 做法 | 结果说明什么 | 下一步 |
| --- | --- | --- | --- |
| 切到全局模式 | 出站模式改为全局，完全退出 Telegram 再打开 | 连上了：规则没覆盖它的服务器 | 回到第三步修规则 |
| 开启 TUN 模式 | 打开 TUN，完全退出 Telegram 再打开 | 连上了：Telegram 不读取系统代理 | 长期用 TUN，或用第二步的应用内代理 |
| 两者都不行 | 以上都试过 | 问题不在这一层 | 换节点对照，再看[梯子连不上](/paicha/tizi-lianbushang/) |

开启 TUN 的方法和注意事项见[TUN 模式](/jiaocheng/tun-moshi/)。两个实验都要先完全退出 Telegram，因为旧连接会沿用旧的路径。

还有一个容易被忽略的小变量：设备时间严重偏差时，很多加密连接会失败。如果以上都没问题，顺手核对一下系统时间，参考[证书错误与系统时间](/paicha/zhengshu-shijian/)。

Telegram 一直连接中的问题，往往在前三步里就能找到线索。第四步的作用是确认你的判断，而不是逐个试运气。

## 下一步：连上之后把设置固定下来

找到原因后，别忘了把结果固定，免得下次再来一遍。

- **用了应用内代理**：记下客户端的端口，以后改端口要同步改这里。
- **开了 TUN**：确认你需要长期开着，还是只在需要时开。
- **规则缺失**：更新规则集后复查一次，同时留意其他同类应用，类似情况见[某个 App 不走代理](/paicha/app-buzou-daili/)。
