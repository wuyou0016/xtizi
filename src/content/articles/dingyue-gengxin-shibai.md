订阅更新失败，一般是五种原因之一：订阅域名在你当前的网络下打不开，订阅被重置或套餐已过期，链接复制得不完整，订阅格式和客户端不匹配，或者客户端、内核版本太旧。不用靠猜，先读客户端给出的报错文字，再用浏览器直接打开订阅链接，就能排掉一半。下面逐个讲怎么验证、怎么处理。

## 先读报错：提示的字样已经说明了一半

客户端更新订阅时，给出的提示往往直接指向原因。下表是常见的对应关系：

| 提示的大意 | 常见对应原因 | 看哪一节 |
| --- | --- | --- |
| 超时、连接被重置、无法解析主机 | 订阅域名在当前网络下不可达 | 原因一 |
| 未找到、拒绝访问、认证失败 | 链接失效、被重置或套餐过期，也可能是链接不完整 | 原因二、原因三 |
| 解析错误、格式错误、不是有效配置 | 格式与客户端不匹配，或内容被截断 | 原因四、原因三 |
| 不支持的类型、未知字段 | 客户端或内核过旧 | 原因五 |
| 提示成功，但节点为空 | 套餐过期后订阅内容为空，或被客户端过滤 | 原因二、成功后的核对 |
| 证书错误 | 系统时间不准，或网络被干扰 | 见[证书与系统时间](/paicha/zhengshu-shijian/) |

这些状态和文字是常见的通用约定，机场实际返回什么由它自己的后台决定，以你看到的为准。排查时同样遵守一条：一次只改一处，改完再更新一次。

## 原因一：订阅更新失败，往往是订阅域名在当前网络下打不开

客户端更新订阅，本质是向订阅链接这个网址下载配置。这个网址在你当前的网络下打不开，更新当然失败，和节点好不好没有关系。

**怎么验证。** 不开代理，用浏览器直接打开订阅链接。能看到一大段文本，说明域名可达；一直转圈或打不开，说明不可达。也可以用命令行：

```
curl -I "你的订阅链接"
```

链接一定要放在引号里，因为里面常有 & 符号。能返回一行 HTTP 状态行，说明可达；一直没有反应或报连接错误，说明不可达。提醒一句：订阅链接带着你的专属密钥，不要发给别人，也不要贴到在线工具里，泄露后的处理见[订阅链接泄露了怎么办](/bikeng/dingyue-xielou/)。

**怎么处理，由易到难：**

1. 换网络再更新，比如切到手机热点。
2. 让客户端通过代理更新。如果节点列表里还有能用的节点，先连上，再更新订阅。多数客户端有“使用代理更新订阅”之类的选项，名称以版本为准。
3. 看机场是否发布了备用订阅地址。不少机场会在公告里提供备用域名，官网打不开时看[机场官网打不开](/paicha/guanwang-dabukai/)。
4. 如果所有节点都已失效又更新不了，就陷入了“先要更新、更新要先能上网”的死结。这时借助手机热点或备用线路过渡，思路见[备用机场要不要买](/zhinan/beiyong-jichang/)。

## 原因二：订阅链接失效，被重置或套餐已过期

机场后台一般有“重置订阅链接”的功能，重置之后旧链接立刻失效。你自己重置过、或者怀疑泄露后主动重置，客户端里保存的旧链接都会更新失败。套餐过期后，订阅也可能返回空内容或错误。

**怎么验证。** 登录机场官网的用户中心：

1. 看套餐的到期时间和剩余流量。
2. 看页面上当前显示的订阅链接，和客户端里保存的是否一致。
3. 重新复制一次用户中心里的订阅链接。

**怎么处理。**

- 已经到期：续费，更新订阅。
- 链接被重置：复制新链接，在客户端里把原订阅的链接替换掉，再更新。
- 你没有重置，链接却失效：要考虑链接是否泄露、被他人重置，处理方法见上面的链接。

## 原因三：订阅链接复制不完整

这种情况看起来最低级，其实最常见。症状通常是“解析错误”，或者提示未找到。

常见的几种情形：

- 聊天软件把一长串链接换行或截断了；
- 链接末尾少了几个字符；
- 首尾多了空格或换行；
- 链接里有多个参数，& 后面的部分丢了。

**怎么验证。** 把链接粘贴到纯文本编辑器里，看它是不是一整行、是不是以 https:// 开头、末尾有没有多余的字符，再和用户中心里的比对前后几位。链接的结构大致如下（示例是虚构的，仅演示结构）：

```
https://SUBSCRIPTION_DOMAIN/PATH/subscribe?token=YOUR_TOKEN
```

**怎么处理。** 回到用户中心，用“复制”按钮重新复制，不要经过聊天软件转发，粘贴时删掉首尾空格。

## 原因四：订阅导入失败，格式与客户端不匹配

机场的订阅内容常见几种格式，不同客户端认的格式不同。格式不对时，更新或首次导入会失败，提示解析错误，或者导入成功但节点是空的。

**怎么验证。** 在浏览器里打开订阅链接（请在自己的电脑上操作），看内容的样子：

| 内容的样子 | 通常是什么格式 | 常见适用的客户端 |
| --- | --- | --- |
| 带缩进的文本，里面有 proxies 之类的字段 | Clash 配置（YAML） | Clash 系客户端，如 Clash Verge Rev、Clash Party、FlClash、Clash Meta for Android、ClashX Meta |
| 一大段看不出含义的字母数字 | 通用订阅（编码后的节点链接列表） | v2rayN、v2rayNG 这类 V2Ray/Xray 系客户端 |
| 以大括号开头的结构化文本 | sing-box 配置（JSON） | sing-box 系客户端 |

表里只是常见对应，同一个客户端是否还能识别别的格式，以它自己的文档为准。多数机场的用户中心会按客户端类型提供不同的订阅入口，或者让你在复制时选择类型。

**怎么处理。**

1. 到用户中心选对应客户端的订阅类型，重新复制链接。
2. 或者换一个支持你拿到的格式的客户端，可以对照[客户端选择工具](/gongju/kehuduan-xuanze/)。
3. 实在没有对应的格式，才考虑订阅转换。转换的原理和风险见[订阅转换是什么](/jiaocheng/dingyue-zhuanhuan/)：转换服务会收到你的订阅链接，不要交给来历不明的在线站点。

各客户端导入订阅的通用步骤，在[订阅链接怎么用](/jiaocheng/dingyue-daoru/)里有，不熟悉的话对着走一遍。

## 原因五：客户端或内核版本过旧

机场的订阅里会用到新的协议或新的配置字段。旧的客户端或内核解析不了，就会提示不支持的类型或未知字段。

Clash 这个名字下尤其容易踩这个坑：原版 Clash 内核和 Clash for Windows 已在 2023 年底停更，现在说的 Clash 多指 mihomo（Clash Meta）内核及基于它的客户端。如果你还在用停更的旧客户端，遇到新协议解析不了，就应该换到仍在维护的客户端，背景见[Clash 是什么](/zhinan/clash-shi-shenme/)。

**怎么验证。**

1. 打开客户端的日志，看有没有“不支持”“未知”之类的字样。
2. 在客户端的“关于”里看当前版本，再和官方仓库发布页的最新版对比。具体版本以官方页面为准，选梯子不在文章里写版本号。

**怎么处理。** 只从官方来源更新。本站每个客户端的下载页都链接到官方仓库，例如[Clash Verge Rev 下载](/xiazai/clash-verge-rev/)。不要装来路不明的安装包，修改版客户端的风险见[破解版客户端](/bikeng/pojie-kehuduan/)。有的客户端把内核更新单独放在设置里，也要一并检查。

## 订阅更新失败排除后，怎么确认拿到的是完整订阅

提示“更新成功”不等于拿到了可用的订阅。更新后逐项核对：

1. 看节点数量，是否和之前或用户中心里说明的大致一致。
2. 看订阅卡片上的到期时间和流量，是否有显示（机场提供时才有）。
3. 选一个节点实际打开一个网站，确认能用。

| 现象 | 说明什么 | 下一步 |
| --- | --- | --- |
| 更新成功，但节点很少或为空 | 套餐过期返回了空内容，或被客户端的过滤设置排除 | 核对套餐状态，检查客户端里的订阅过滤或排除设置 |
| 节点列表出现了，但全是超时 | 订阅拿到了，问题在线路或本机 | 见[节点超时](/paicha/jiedian-chaoshi/) |
| 提示成功，节点还是旧的 | 选中的不是刚更新的订阅，或结果被缓存 | 确认当前选中的订阅，重新手动更新 |

## 下一步：把有效订阅留好，把意外排除在外

- **找到了原因**：按对应一节处理。订阅更新失败排除之后，在客户端里把更新间隔设成合适的值，别设得太频繁。
- **五种都不是**：回到[梯子连不上的六步排查](/paicha/tizi-lianbushang/)，检查本机网络、套餐状态和服务商公告。
- **订阅域名经常打不开**：说明这家的订阅入口对你的网络不友好。先保留一个备用线路，再评估要不要换家，可以从[机场推荐](/tuijian/)里看订阅格式和周期，先月付验证。
- **平时的习惯**：订阅链接当作密码保管，换设备时在用户中心里重新复制，不要在聊天里转发。
