Netflix 提示代理，意思是平台把你当前的出口识别成了 VPN 或代理，于是要么直接弹出错误提示拒绝播放，要么表现异常，比如常被提到的“只剩自制剧”。这通常不是客户端设置错了，而是出口 IP 被识别。下面先分清你遇到的是哪一种，再按由易到难的顺序处理，最后说明为什么没有一劳永逸的办法。

## 先分清：奈飞代理提示和只剩自制剧是两种现象

两种现象都和出口被识别有关，但表现和排查起点略有不同。

| 页面表现 | 说明什么 | 下一步 |
| --- | --- | --- |
| 弹出提示，说检测到代理或 VPN，无法播放 | 出口被识别，播放被直接拒绝 | 从第一步开始 |
| 能进首页，但片库里只有 Netflix 自制内容 | 常见原因是出口被当成代理（官方没有公开规则，这是用户常见的描述） | 同样从第一步开始 |
| 部分作品能播，部分提示当前不可观看 | 这些作品在平台识别到的地区没有授权 | 先确认出口地区是否符合预期 |
| 以前能看，今天突然不行 | 出口 IP 的状态变了，或这个节点被识别了 | 换同地区的其他节点 |
| 手机 App 不行、网页可以，或者相反 | 两条路径的 DNS、IPv6 或分应用设置不同 | 对照两边设置，见[App 不走代理](/paicha/app-buzou-daili/) |
| 所有节点结果完全一致 | 更可能是你这一侧的共性设置，或整家线路被识别 | 做第三步、第四步 |

整个排查只守一条原则：一次只改一处，改完彻底退出应用再打开。

## 官方怎么说：提示 VPN 或代理时，建议关闭后重试

Netflix 帮助中心的[官方说明页](https://help.netflix.com/en/node/277)标题就是“Netflix says, 'You seem to be using a VPN or proxy.'”。页面写明：VPN 应用或服务会让设备或网络看起来像是从别处连接的，可能导致这条错误或其他问题；如果问题持续，官方建议关闭 VPN 后再试。页面还写明，VPN 不支持观看直播活动，也不支持广告方案。

这里有两层含义。第一，官方说明的重点是“被识别后会报错，建议关闭”，没有给出可以绕过识别的办法，所以遇到 Netflix 提示代理时，指望一个固定的设置一次解决，并不现实。第二，片库内容按地区授权，同一部作品在不同地区能否播放不同，所以出口落在哪个地区，会直接决定你看到什么；至于“只剩自制剧”，官方页面没有这样描述，它是用户常见的现象描述，可以当作出口被识别的线索，但不是官方结论。

选梯子手里没有解锁方面的测试结果，也不会替你判断某个节点现在能不能看。我们能给的是排查方法和判断依据，结论要你自己验证。关于“解锁”这件事本身，为什么同一个节点时灵时不灵，见[流媒体解锁](/zhinan/liumeiti-jiesuo/)。

## 第一步：彻底退出重开，确认出口地区

客户端的片库有时不会立刻随着出口变化而刷新，所以每次改动之后都要先重新开始。

1. 完全退出 Netflix 应用，网页版则关闭标签页，再重新打开。
2. 连上节点后，用查询公网 IP 的网页确认一下出口地区，看是不是你预期的那个。
3. 记下这个节点的名字和现象，作为后面对照的基线。

如果出口根本不是你以为的地区，先解决节点本身的问题。节点名与真实出口不一致的情况，见[原生 IP](/zhinan/yuansheng-ip/)和[节点地区](/zhinan/jiedian-diqu/)两篇。

## 第二步：同地区换节点，一次只换一个

同一个地区的多个节点，往往来自不同的服务器和 IP 段。一个被识别了，另一个不一定。

1. 在同一地区换一个节点。
2. 彻底退出应用，重新打开，看片库和播放。
3. 记录结果，再换下一个。每次只换一个。

看待套餐里的流媒体标注，要有分寸。机场在节点名或说明里标注适合流媒体，是商家自述，只能当作筛选线索，不是承诺。数据中心机房的 IP 更容易被识别，所谓“原生 IP”也没有统一标准，需要靠你自己的验证来确认。

选定能用的节点之后，尽量固定下来，不要让“自动选择”类策略组去切换出口。

## 第三步：让 DNS 和出口保持一致，排除 Netflix 无法观看的共性原因

平台具体用哪些线索判断来源，官方没有公开说明，所以这一步不是一定有效的办法，而是排除变量：让域名解析和实际流量走同一条路径，位置保持一致。

如果你的 DNS 请求走的是本地运营商，而视频流量走的是海外节点，两侧的位置是不一致的。可以按下面的方向处理：

1. 在客户端里让域名解析经过代理，或使用能避免本地解析的 DNS 模式，原理见[Clash DNS](/jiaocheng/clash-dns/)。
2. 暂时关闭浏览器自带的加密 DNS，避免它绕开客户端的设置。
3. 确认 App 没有使用自己内置的 DNS，必要时在手机上用 VPN 方式运行的客户端接管全部流量。
4. 用 [DNS 泄漏检测](/paicha/dns-xielou/)的方法核对一次，看实际的解析请求去了哪里。

这一步改的是整台设备的解析方式，影响面比换节点大。改完要验证其他网站是否正常。

## 第四步：排除 IPv6 的影响

如果你的网络支持 IPv6，而代理只接管了 IPv4，就会出现一个隐蔽的问题：一部分请求通过 IPv6 直接从本机发出，平台看到的是你的真实地区，与节点的出口不一致，这样的组合也容易被识别为代理。

做法是做一个对照实验：

1. 在客户端里找到 IPv6 相关的开关，关闭后重新连接。
2. 或者临时在系统的网络设置里关闭 IPv6。
3. 彻底退出 Netflix 重新打开，看现象有没有变化。

有变化，说明 IPv6 是原因之一，可以保持关闭；没有变化，就把设置恢复原状，不要留着不明的改动。

每一轮对照建议记下来，几行就够，后面判断是节点问题还是共性设置时会用到：

| 轮次 | 改动了什么 | 节点 | 现象 |
| --- | --- | --- | --- |
| 基线 | 无 | 节点 A | 提示代理或只剩自制剧 |
| 第 2 轮 | 同地区换节点 | 节点 B | 填写实际现象 |
| 第 3 轮 | 调整 DNS | 节点 B | 填写实际现象 |
| 第 4 轮 | 关闭 IPv6 | 节点 B | 填写实际现象 |

以上是举例。如果所有轮次的现象完全一样，更像是这家线路整体被识别，下一步就是向客服了解，或者考虑换一种线路类型。

## 联系机场客服时，该问什么

前面几步都做完仍不行，可以向机场客服了解情况。提问尽量具体：

- 想用的地区里，哪些节点有流媒体标注，标注是怎么得出的。
- 有没有专门的流媒体节点，倍率和流量规则是怎样的。
- 当前节点近期有没有更换过出口。
- 如果最终无法使用，有没有退款或试用的政策，规则见[机场能退款吗](/bikeng/jichang-tuikuan/)。

客服的回答也属于商家自述。拿到回复后，仍然要自己按前面的步骤验证一遍，不要把口头回复当作承诺。

## 下一步：没有一劳永逸，但可以少走弯路

遇到 Netflix 提示代理，不要认定是自己操作失误。平台在持续更新识别方式，节点的出口 IP 也会变化，所以“今天能看、明天不行”是常态。这是平台和节点之间的博弈，没有谁能给出一劳永逸的办法，任何宣称长期稳定可用的说法，都要打问号。

在这个前提下，务实的做法是：

1. **用月付或试用验证**，不要为了 Netflix 一次买长周期。周期怎么选，见[机场年付还是月付](/zhinan/nianfu-haishi-yuefu/)。
2. **把能用的节点记下来**，固定使用，同时留一两个同地区的备选。
3. **选购前看清楚**：需要哪些地区、有没有试用。奈飞方向的选购要点，见[Netflix 梯子怎么选](/changjing/netflix/)，再到[机场推荐](/tuijian/)里按地区筛选。
4. **还没想好**：用[选梯子向导](/gongju/xuan-tizi-xiangdao/)先定预算和使用场景。
