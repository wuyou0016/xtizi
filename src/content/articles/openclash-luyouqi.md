OpenClash 教程里最重要的一句话是：路由器上的改动会影响家里每一台设备，所以先想清楚怎么恢复，再想怎么配置。OpenClash 是 OpenWrt 的插件，基于 Mihomo 内核，装好后可以让局域网里的设备透明地走代理，不用在每台设备上装客户端。下面按前提、安装、订阅、模式、名单、恢复、验证的顺序讲，难度比手机和电脑客户端高，请不要在家人正在用网的时候试验。

## OpenClash 教程之前：路由器部署要先想清的四件事

把梯子装到路由器上，和在手机上装个应用完全不同。

| 事项 | 为什么重要 | 你要做什么 |
| --- | --- | --- |
| 固件 | OpenClash 只能装在 OpenWrt 上 | 确认路由器运行 OpenWrt 或基于它的固件，原厂固件装不了 |
| 空间与内存 | 插件、内核文件和配置都要占空间，运行时也吃内存 | 留出余量，空间紧张的老机型不建议折腾 |
| 恢复手段 | 配错了会让全家断网 | 动手前先备份路由器配置，并学会停用的办法 |
| 影响范围 | 所有联网设备都会受到影响 | 选家里没人用网的时段操作，通知家人 |

固件不是 OpenWrt 的人，别急着刷机，因为刷机本身有风险，且与机型强相关。更省心的替代方案是继续在电脑上用客户端，再通过局域网把代理共享给其他设备，见[局域网共享代理](/jiaocheng/juyuwang-gongxiang/)；电视这类设备的几种做法，见[电视怎么用梯子](/jiaocheng/dianshi-tizi/)。路由器上的整体插件对照，在[路由器梯子下载](/xiazai/luyouqi/)里。

还有一点常被忽略：路由器上的所有设备共用同一个出口。套餐的设备数限制按什么口径计算，各家规则不同，买之前读一遍[梯子能几台设备同时用](/zhinan/duo-shebei/)。

## 安装前提：OpenWrt、依赖包和内核文件

插件的安装分四步，顺序不能乱。

1. **确认系统和架构。** 登录路由器的命令行，查看系统信息文件，确认 OpenWrt 的版本信息和处理器架构，后面选内核文件要用到。系统信息文件的位置和命令以 OpenWrt 文档为准。
2. **检查剩余空间。** 在管理界面或命令行里看剩余的存储空间，没有余量就别装。
3. **安装依赖包。** 官方仓库的说明里列有依赖清单，大致分为下面几类：

| 依赖类别 | 作用 |
| --- | --- |
| 完整版 dnsmasq | 替换系统自带的精简版，提供插件需要的 DNS 能力 |
| 常用命令行工具 | 供插件脚本调用，例如 bash、curl 一类 |
| TUN 内核模块 | 提供虚拟网卡支持 |
| 防火墙转发相关模块 | 用于透明代理，随防火墙实现不同而有差异 |
| 配置解析相关组件 | 用于处理 YAML 格式的配置 |

清单会随版本调整，以[官方仓库](https://github.com/vernesong/OpenClash)的说明为准。包管理器可能是 opkg，也可能是 apk，取决于 OpenWrt 的版本。要特别注意：替换完整版 dnsmasq 会短暂中断路由器的 DHCP 和 DNS 服务，所以要先把需要的安装包下载到本地，再操作。

4. **安装插件，放置内核文件。** 从发布页下载与你的包管理器匹配的插件包，上传到路由器安装。OpenClash 本体不含内核，需要另外放置与架构一致的内核文件，一般放在插件目录下的 core 子目录，文件名和位置以官方说明为准。插件里通常提供更新内核的功能，但它要从 GitHub 下载，路由器自己能否访问是个问题，不通时就手动上传。

装好之后，在管理界面的“服务”菜单下应该能看到 OpenClash 的入口。页面顶部的数据卡会显示插件的版本和官方地址，下载说明见[OpenClash 下载页](/xiazai/openclash/)。

## OpenClash 订阅怎么配：添加、转换开关与更新

订阅页的名称是“配置订阅”或类似，具体标签以当前版本为准。

1. 进入插件的订阅管理页，选择添加。
2. 填写订阅名称，粘贴 `https://example.com/你的订阅链接`。
3. 留意“订阅转换”之类的开关，下面单独讲。
4. 保存并应用，然后执行更新，让路由器去下载配置。
5. 在配置文件管理里，确认新配置已经出现并被选中。

关于订阅转换，需要多留心。插件里内置的转换功能依赖一个转换服务，转换时订阅链接会被发送出去，默认指向哪里，以当前版本和你的设置为准。

| 你拿到的订阅 | 建议 |
| --- | --- |
| 本身就是完整的 Clash 配置 | 关掉转换，直接使用，链接不经过第三方 |
| 只有通用格式订阅 | 先向机场要 Clash 格式地址；实在要转换，弄清楚转换服务在谁手里，见[订阅转换是什么](/jiaocheng/dingyue-zhuanhuan/) |

订阅链接等同账号凭证，泄露后的处理见[订阅链接泄露了怎么办](/bikeng/dingyue-xielou/)。通用的订阅概念见[订阅链接怎么用](/jiaocheng/dingyue-daoru/)。

路由器上更新订阅有个特点：下载动作发生在路由器上，而不是你的电脑上。电脑浏览器能打开订阅链接，只说明电脑所在的网络能访问，路由器能否访问是另一回事。更新失败时要在路由器上测试，排查思路见[订阅更新失败怎么办](/paicha/dingyue-gengxin-shibai/)。

## OpenClash 设置里最关键的一项：运行模式

运行模式决定插件如何处理 DNS 和流量，是影响兼容性最大的设置。最常被比较的是 Fake-IP（增强）与 Redir-Host（兼容）。

| 对比项 | Fake-IP | Redir-Host |
| --- | --- | --- |
| 做法 | 先给域名分配一个假的内部地址，再按域名走规则 | 先解析出真实地址，再按规则处理 |
| 优点 | 规则匹配直接，解析环节少 | 与依赖真实地址的应用兼容性更好 |
| 可能的问题 | 个别应用、联机游戏、局域网设备依赖真实地址时会异常 | 解析环节多，容易受 DNS 污染等因素影响 |
| 适合 | 多数家庭使用，首选 | 遇到 Fake-IP 兼容问题时的备选 |

两种模式的原理，见[Clash DNS 怎么设置](/jiaocheng/clash-dns/)和术语页[Fake-IP](/cidian/fake-ip/)。

选择思路：

- **没有特殊需求。** 先用 Fake-IP，跑通再说。
- **个别设备或应用异常。** 先试着把这些设备加入不走代理的名单，下一节会讲，不要一上来就全局换模式。
- **换到 Redir-Host 后问题依旧。** 看插件日志，通常能定位是 DNS 问题还是规则问题。

插件里还有混合模式、TUN 等运行方式的选项，涉及的底层依赖更多。第一次部署，不要同时改多项，一次只调一个变量。切换模式后重启插件，并清理设备上的 DNS 缓存，才能看到真实效果。

## 局域网里谁走代理，谁不走：访问控制名单

路由器代理的一个现实问题：电视盒子、游戏机、智能家居设备、家人的手机，未必都需要走梯子，有的甚至会因此异常。插件的流量控制里，一般有按设备设置的访问控制。

| 名单思路 | 含义 | 适合 |
| --- | --- | --- |
| 排除名单 | 名单里的设备不走代理，其余设备都走 | 大部分设备要走代理，只有少数例外 |
| 限定名单 | 只有名单里的设备走代理，其余都直连 | 只让少数设备走代理 |

界面里对应的标签名不一定直观，有的叫黑名单，有的叫白名单，哪一种是“排除”、哪一种是“限定”，务必读界面里的说明，不要凭名字猜，设置完用设备验证。

使用名单的注意点：

1. **设备需要固定的地址。** 名单通常按 IP 或设备标识识别，地址变了名单就失效。先在路由器上为这些设备设置固定地址。
2. **改完要重启插件。** 然后用该设备自己的出口 IP 查询页面验证。
3. **不要把整个家里的网络当实验场。** 先只拿自己的一台设备测试，没问题再扩大。

## 出问题怎么快速恢复上网：三种停用办法

这一节建议在动手配置之前就读完。

| 办法 | 做法 | 适合 |
| --- | --- | --- |
| 管理界面停用 | 在插件的运行状态页点击停止，并关闭开机自启 | 管理页面还能打开 |
| 命令行停用 | 登录路由器命令行，执行 `/etc/init.d/openclash stop` 停止服务，再用 `/etc/init.d/openclash disable` 取消开机自启 | 管理页面打不开，但命令行能登录 |
| 恢复备份 | 用网线直连路由器，进入管理页面，恢复之前导出的配置备份 | 前两种都无效 |

两点提醒。

- **只停止不取消自启，重启后它又会起来。** 表现为刚恢复又断网，要把自启关掉。
- **每次改动前先导出一份路由器的配置备份。** 这是最后的退路。

整个家里突然上不了网时，先别慌着重装，按这个顺序处理：停用插件、重启路由器、确认基础网络恢复，再回头看日志。通用的排查步骤见[梯子连不上怎么办](/paicha/tizi-lianbushang/)。

## 验证生效与常见卡点

1. **看运行状态。** 插件页显示正在运行，内核版本信息可以读到。
2. **看日志。** 日志里没有持续的错误，订阅更新成功。
3. **用一台设备验证出口 IP。** 在该设备上打开显示出口 IP 的查询页面，开关插件各看一次。
4. **验证名单。** 被排除的设备出口 IP 应该是你原本的网络，其他设备应该是节点所在的网络。
5. **验证国内外。** 国内网站应当直连，国外网站应当走代理。
6. **停用后验证恢复。** 停止插件之后，所有设备应当恢复到原来的网络状态。

卡点汇总：

| 症状 | 常见原因 | 先试什么 |
| --- | --- | --- |
| 插件启动失败，日志提示内核问题 | 内核文件缺失、架构不对或没有执行权限 | 核对架构，重新放置内核文件 |
| 启动后全家断网 | DNS 被接管后配置有误，或配置文件无效 | 先停用，再看日志，检查订阅与模式 |
| 订阅更新失败 | 路由器自己访问不了订阅域名 | 在路由器上测试访问，必要时手动导入配置文件 |
| 个别设备打不开网页或联机异常 | Fake-IP 兼容问题 | 把该设备加入排除名单，或评估换模式 |
| 路由器负载高、网速变慢 | 硬件性能不足 | 减少同时开启的功能，评估更换设备 |

## 下一步：先在一台设备上跑通，再让全家上线
