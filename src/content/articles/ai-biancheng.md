写代码用的 AI 编程梯子，和平时上网的梯子可以是同一条线路，区别在接入方式：补全、对话和代理任务的请求是从编辑器进程、扩展和终端里发出去的，这些程序不一定理会系统代理。所以开发者常遇到的不是梯子不行，而是浏览器能开、编辑器里一直转圈。这篇先讲流量怎么走，再讲线路怎么选。

## AI 编程工具的流量从哪里发出

排查之前先建立一张地图：哪个程序在发请求，它默认听不听系统代理。

| 流量来源 | 典型场景 | 默认是否跟随系统代理 | 常用处理 |
| --- | --- | --- | --- |
| 浏览器 | 登录、授权跳转、网页版对话 | 通常跟随 | 一般不用额外设置 |
| 编辑器主进程与扩展 | 代码补全、侧边栏对话、扩展市场 | 取决于编辑器设置 | 在编辑器里填代理地址，或开 TUN |
| 独立的 AI 编辑器 | 自带的对话、整库索引 | 取决于应用实现 | 应用内网络设置，或开 TUN |
| 终端里的命令行工具 | 命令行 AI 助手、git、包管理器 | 通常不跟随 | 设置环境变量，或开 TUN |
| 远程开发环境 | SSH 主机、容器、WSL 里的扩展和命令 | 不受本机梯子影响 | 在远端配置代理，或让功能回到本机执行 |

这张表解释了一个常见的困惑：同一台电脑上，浏览器、编辑器、终端可能分别走了三条不同的路。系统代理只是一个“建议”，程序可以不采纳，原理见[系统代理](/jiaocheng/xitong-daili/)。某个程序就是不走代理时，通用的排查思路在[App 不走代理](/paicha/app-buzou-daili/)里。

## Copilot 梯子：让编辑器和扩展走代理的两种做法

以 GitHub Copilot 为例，它作为扩展运行在编辑器里，补全请求由编辑器一侧发出。让它走代理有两种做法。

**做法一：在编辑器里填代理地址。** 主流编辑器的设置里都有 HTTP 代理项，例如 VS Code 的 `http.proxy`，JetBrains 系 IDE 的设置里也有对应入口。把它指向梯子客户端的本地端口，格式类似 `http://127.0.0.1:端口`，端口号以你客户端设置页显示的为准。Copilot 对网络和代理的要求、支持哪些配置方式，[GitHub 文档](https://docs.github.com/en)里有专门的说明，以文档为准。

**做法二：打开 TUN 模式。** TUN 在系统层面建一张虚拟网卡，所有程序的流量都会经过它，不需要逐个程序设置。Clash Verge Rev、Clash Party、v2rayN 等桌面客户端都提供这个功能，开启方法见[TUN 模式](/jiaocheng/tun-moshi/)。

两种做法的取舍：

- 做法一改动小，只影响编辑器，适合只有一两个工具要处理的人。
- 做法二覆盖全，终端、容器、各种小工具一次解决，但它接管整机流量，可能与公司 VPN 客户端冲突，也需要管理员权限。开不起来时看[TUN 模式开不了](/paicha/tun-moshi-shibai/)。

还有一个容易忽略的环节：登录。这类扩展登录时会跳到浏览器完成授权，再回到编辑器。浏览器和编辑器如果走了不同的出口，一个在代理后面、一个直连，授权可能卡在回调这一步。让两者走同一条路，问题通常就消失了。GitHub 本身访问慢、克隆卡住的情况，另见[GitHub 梯子](/changjing/github/)。

## Cursor 梯子：流式输出为什么对线路更敏感

Cursor 这类独立的 AI 编辑器，是在 VS Code 开源代码的基础上开发的，代理相关的设置入口与之相近；它自己的网络选项以当前版本的设置页为准。

比“怎么设置”更值得理解的是这类工具的连接特点。对话和生成代码时，结果是一小段一小段流式返回的，一次请求可能持续几十秒甚至更久。这意味着：

- **怕断，不怕慢**。连接中途被重置，输出就停在一半，往往要整段重来。带宽只要够传文本就行。
- **怕抖动**。丢包严重时，表现为输出卡住几秒再继续，或者干脆超时。
- **对代理链路的兼容性有要求**。部分代理环境对长时间保持的连接处理得不好，一些工具因此在网络设置里提供了兼容选项，遇到输出反复卡住时可以去找一找，以当前版本为准。

整库索引、上传上下文这类操作会产生比对话更多的上行流量，但总量仍然远小于看视频。流量不是这个场景的瓶颈。

## 终端里的 AI 工具：环境变量和 TUN 怎么选

终端是开发者踩坑最多的地方。命令行程序大多不读取系统代理，只认环境变量或者自己的配置文件。

临时让当前终端走代理，可以这样写。端口 7890 只是示例，请换成你客户端显示的端口。macOS 和 Linux 的终端里：

```bash
export http_proxy=http://127.0.0.1:7890
export https_proxy=http://127.0.0.1:7890
export all_proxy=socks5://127.0.0.1:7890
```

Windows 的 PowerShell 里：

```powershell
$env:HTTP_PROXY="http://127.0.0.1:7890"
$env:HTTPS_PROXY="http://127.0.0.1:7890"
```

需要注意三点：

1. 这些变量只对当前终端窗口有效，关掉就没了。想长期生效要写进 shell 的配置文件，但那样梯子没开时所有命令都会失败，各有利弊。
2. 不是所有程序都认这些变量。git、npm、Docker 各有各的代理配置，逐个的写法在[终端代理](/jiaocheng/zhongduan-daili/)里。
3. WSL、容器和远程主机有各自的网络环境，里面的 `127.0.0.1` 不一定指向你电脑上的梯子客户端。这时要么让客户端允许局域网连接并改用宿主机地址，要么用 TUN。

如果你每天要用的命令行工具超过三四种，逐个配置的维护成本会超过收益，直接用 TUN 更合理。

## 编程代理的线路怎么选：稳定和固定出口优先

接入方式解决之后，才轮到线路。AI 编程梯子在选线路时的侧重，和看视频几乎相反。

| 你的需求 | 看套餐页的哪个字段 | 怎么读 |
| --- | --- | --- |
| 长时间流式输出不中断 | 线路类型（专线、中转、直连） | 专线和中转通常更强调稳定，但属于商家自述 |
| 账号登录地区保持一致 | 节点地区、出口是否固定 | 选定一个地区长期使用，避免自动跨国切换 |
| 工作时段都能用 | 是否限速、高峰期说明 | 白天和晚上各试几天，自己观察 |
| 电脑、笔记本、服务器都要用 | 同时在线设备数 | 数清楚自己有几台设备 |
| 偶尔拉大体积依赖和镜像 | 月流量与节点倍率 | 补全和对话耗流量少，拉镜像才是流量大头 |

关于专线：机场页面上常见 IPLC、IEPL 这类名词，它们描述的是跨境那一段的传输方式，含义和常见的宣传说法见[IPLC 和 IEPL](/zhinan/iplc-iepl/)。选梯子没有任何线路的稳定性测试数据，无法告诉你哪一家更稳，只能告诉你这个字段值得看，然后用月付去试。按这个维度筛选的入口是[专线机场推荐](/tuijian/zhuanxian/)。

关于固定出口：AI 编程工具背后的模型服务大多按地区提供，并且对账号的登录环境有风控。同一个账号的请求一会儿从这个国家出去、一会儿从那个国家出去，可能触发验证或限制。在客户端里给这些工具的域名指定一个只含同一地区节点的策略组，比依赖自动选择稳妥。这是降低风险的做法，无法保证账号不出问题。

## 自己验证：确认请求真的走了代理

下面的检查能回答两个问题：代理通不通，以及某个程序到底有没有用上它。

1. **看直连出口。** 在没有设置任何代理变量的终端里执行第一条命令，输出里的 `ip` 和 `loc` 是本机直连的出口。
2. **看代理出口。** 执行第二条命令，显式指定代理。`loc` 变成节点所在地区，说明代理本身是通的。
3. **看环境变量是否生效。** 设置好环境变量后再执行第一条命令，结果应当和第二步一致。不一致，说明变量没有被这个终端读到。

```bash
curl -s https://www.cloudflare.com/cdn-cgi/trace
curl -s -x http://127.0.0.1:7890 https://www.cloudflare.com/cdn-cgi/trace
```

4. **看编辑器有没有走代理。** 打开梯子客户端的连接列表，在编辑器里触发一次补全或对话，观察有没有新增的连接、命中了哪条规则、走了哪个节点。列表里完全没有动静，说明编辑器的请求没有经过客户端。
5. **看长连接稳不稳。** 让工具生成一段较长的代码，连续做几次，留意是否中途停住。换一个节点重复，对比差别。
6. **分时段再测一次。** 上午和晚上各做一次第 5 步。只在晚上出问题，多半是线路在高峰期拥堵，而不是配置有错。

这套检查建议在换机场、换客户端或者升级编辑器之后各做一次。

## 下一步：先接通，再挑线路

配 AI 编程梯子的顺序是先让请求走上代理，再评价线路好坏，顺序反了容易白换机场。

- **编辑器里转圈、浏览器正常**：先按“两种做法”一节把编辑器接上代理，再做第 4 步验证。
- **终端超时**：设置环境变量后做前三步验证；工具多就直接上 TUN。
- **能连上但输出经常中断**：换同地区的其他节点对比，并考虑线路类型不同的套餐，到[专线机场推荐](/tuijian/zhuanxian/)或[机场推荐](/tuijian/)里按线路字段筛，先月付。
- **还要用网页版 AI**：地区和 IP 方面的要求见[ChatGPT 梯子](/changjing/chatgpt/)与[Claude 梯子](/changjing/claude/)，建议和编程工具共用同一个地区的出口。

本页下方的数据块列出了资料里标注了专线线路的机场。线路类型来自公开资料，不是选梯子测出来的结果。
