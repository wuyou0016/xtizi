ChatGPT 打不开，先别急着换节点，看清页面上的提示再动手：提示地区不支持，是出口 IP 的问题；一直弹验证，是 IP 被大量共用或节点在来回切换；页面空白或一直加载，多半是分流规则和 DNS；所有节点同时失败，则要先看官方状态页。下面按这几类现象给出排查顺序。

## 先看提示：ChatGPT 打不开有哪几种现象

先对号入座。不同现象，排查的起点完全不同。

| 页面表现 | 说明什么 | 下一步 |
| --- | --- | --- |
| 提示所在国家或地区不受支持 | 服务端看到的访问来源不在支持地区 | 做第二步，查出口 IP |
| 人机验证反复出现，或验证完又回到验证页 | 出口 IP 被大量共用，或连接中途换了出口 | 做第三步 |
| 页面白屏、一直转圈，登录或对话加载不出来 | 部分域名没走代理，或 DNS 解析异常 | 做第四步 |
| 所有节点同时失败，或页面提示服务异常 | 官方故障，或梯子本身没连上 | 做第一步 |
| 能登录，但提示账号被限制或暂停 | 账号一侧的规则 | 看账号被限制那一节 |
| 手机 App 打不开，网页版正常 | App 的网络路径与浏览器不同 | 先确认客户端在手机上是 VPN 方式运行，再看[App 不走代理](/paicha/app-buzou-daili/) |

排查时只守一条原则：一次只改一处，改完关闭页面重新打开。同时换节点又改规则，好了也说不清是哪一处起了作用。

## 第一步：先排除官方故障和梯子没连上

这两种情况下，后面所有的检查都是白费力气，所以放在最前面。

1. 打开 [ChatGPT 状态页](https://status.openai.com/)，看有没有正在处理的事件。官方在故障期间，换哪个节点都没有用，等恢复即可。状态页本身也要走代理才能打开。
2. 随便打开一个和 ChatGPT 无关、需要代理的国外网站。它也打不开，说明是梯子本身的问题，转去看[梯子连不上怎么办](/paicha/tizi-lianbushang/)。
3. 记下当前的出站模式是规则还是全局，第四步要用。

状态页正常、别的国外网站也能打开，再往下查。

## 第二步：ChatGPT 地区不支持，看出口 IP 而不是节点名

OpenAI 在帮助中心公布了[ChatGPT 支持的国家和地区](https://help.openai.com/en/articles/7947663-chatgpt-supported-countries)。中国大陆不在这份列表之中；至于别的地区现在是否受支持，请直接看官方页面，选梯子不替官方整理名单。请遵守所在地法律法规，选梯子不提供法律意见。

判断依据是服务端看到的出口 IP，而不是节点名字。按下面的步骤查：

1. 连上节点，找一个能查询公网 IP 归属地的网页打开。先确认这个页面本身走了代理：如果它显示的是你本机的地址，说明它被分流判成了直连。
2. 记下显示的国家或地区，对照官方页面。
3. 不在支持地区，换一个出口位于官方列表内地区的节点，回到第 1 步重新确认。
4. 出口在支持地区却仍然提示不支持，进入下面的排查。

可能的原因：

- 部分请求没有走代理。规则模式下漏了域名时，一部分请求从本机直接发出，服务端看到的还是你的真实地区。临时切到全局模式对照，见第四步。
- 本机的 IPv6 直接出了网。如果代理只接管了 IPv4，走 IPv6 的请求会暴露真实地区。可以在客户端里关闭 IPv6，或临时关闭本机 IPv6 做对照，原理在[Netflix 提示代理](/paicha/netflix-daili-tishi/)里有更细的说明。
- 查询页给出的归属地来自它自己的 IP 库，几个页面的结果有时对不上。遇到矛盾时，以 ChatGPT 的实际表现为准，再换同地区的其他节点试。

节点名不等于出口位置，很多线路是入口和出口分开的结构，见[节点地区](/zhinan/jiedian-diqu/)和[原生 IP](/zhinan/yuansheng-ip/)两篇。

## 第三步：人机验证反复出现，先固定节点

验证循环有两个常见来源，处理方向不同。

**来源一：连接途中换了出口。** 客户端里“自动选择”“负载均衡”这类策略组会在后台切换节点，每换一次，出口 IP 就变一次，验证状态随之作废。处理办法是把 ChatGPT 使用的策略组改为手动选择，固定一个节点。策略组的用法见[策略组](/jiaocheng/celue-zu/)。

**来源二：出口 IP 被大量共用。** 同一个 IP 背后有很多人，平台看到的是异常流量。处理办法是同地区换另一个节点对照：一个行、一个不行，问题就在那个 IP 上。

然后排除浏览器环境：

1. 用无痕窗口或一个干净的浏览器配置文件打开页面。
2. 暂时关掉广告拦截、隐私类扩展。
3. 确认没有禁用 Cookie 和脚本。
4. 核对系统时间是否准确。

完成验证后不要频繁刷新，也不要同时开很多标签反复登录。验证是平台的防护措施，不要去使用自动化工具或脚本通过它。要是谷歌搜索也总弹出验证，成因往往相同，处理办法见[谷歌验证码](/paicha/google-yanzhengma/)。

## 第四步：页面空白、一直加载，常是分流规则和 DNS

ChatGPT 的页面由多个域名共同支撑，包括主站、静态资源、登录和接口。规则模式下，只要其中几个域名没有命中代理规则，这些请求就会直连，结果是页面残缺、一直转圈，或者能打开但登录、对话加载不出来。这类 ChatGPT 打不开的情况最容易被误判成线路问题，也就是常说的 ChatGPT 无法访问。

1. 临时切到全局模式，重新打开页面。变好了，说明规则模式下漏了域名；没变化，往下看 DNS 和浏览器。
2. 找出漏掉的域名。在浏览器里按 F12 打开开发者工具，切到网络面板，刷新页面，看红色失败的请求的域名。也可以在客户端的连接页里看哪些域名走了直连。
3. 更新规则集，或者给漏掉的域名补一条走代理的规则：

```yaml
rules:
  - DOMAIN-SUFFIX,<失败请求里看到的域名>,<走代理的策略组名>
  # 放在国内直连规则和兜底规则之前
```

4. 强制刷新页面，或清除该站点的缓存和数据，避免旧状态干扰。
5. DNS 异常时，参考[Clash DNS](/jiaocheng/clash-dns/)检查域名解析的设置，同时关闭浏览器自带的加密 DNS 做对照。

规则模式与全局模式的区别见[规则模式、全局模式、直连模式](/jiaocheng/guize-quanju-zhilian/)。

## 账号被限制：梯子解决不了

如果你能登录，但页面提示账号被限制、暂停，或者出现和账号相关的警告，这是平台一侧的规则，与线路无关。OpenAI 对在支持地区之外使用的情况有说明，具体措辞以官方页面为准。

这种情况要明确三点：

- 换节点没有用，反而可能让情况更复杂。
- 申诉和说明只能走官方帮助中心的渠道。
- 不要用注册新账号、提供不实信息之类的办法去规避，这类做法会带来更多问题。

付费订阅、账单相关的问题同样属于平台，梯子只负责网络连接，改变不了账号的状态。

## 做完对照实验，怎么确认真的修好了

每一次改动都应该有一个明确的“好了”的标准。建议按下面的顺序走一遍完整流程：

| 检查项 | 通过的标志 | 不通过怎么办 |
| --- | --- | --- |
| 状态页 | 没有进行中的事件 | 等官方恢复 |
| 出口 IP | 地区在官方页面的列表内 | 换节点，重新查 |
| 页面加载 | 首页、登录页都正常显示 | 回到第四步 |
| 完整登录 | 登录后进入对话界面，没有验证循环 | 回到第三步 |
| 发一条消息 | 正常得到回复 | 换同地区节点对照 |
| 过一段时间再试 | 隔几个小时仍可用 | 检查是否有策略组在自动切换 |

通过后，把这个节点记下来，固定使用。不要因为一次顺利就频繁试别的节点。

## 下一步：把节点固定下来，再看要不要换机场

- **已经找到能用的节点**：放进一个手动选择的策略组，不要交给自动选择去切换。
- **同一家的节点轮流试过都不行**：问题可能出在这家的 IP 质量，具体字段怎么核对，见[ChatGPT 梯子怎么选](/changjing/chatgpt/)，再到[机场推荐](/tuijian/)里按海外地区筛选。
- **还要用其他 AI 工具**：Claude 的排查思路类似，细节见[Claude 用不了](/paicha/claude-yongbuliao/)。
- **不确定自己需要什么配置**：用[选梯子向导](/gongju/xuan-tizi-xiangdao/)先定预算和设备数。

页面底部的数据块只能说明资料里这些机场登记过哪些海外地区，至于这些地区的节点此刻能否打开 ChatGPT，还得靠你按上面的步骤自己验证。
