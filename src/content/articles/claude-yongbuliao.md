Claude 用不了，大致分四种情况：提示所在地区不可用、登录或验证反复循环、账号被限制，以及官方服务本身出了问题。前两种可以通过出口地区和节点设置自己排查，后两种换多少个节点都没有用。下面先教你区分，再按顺序处理。

## 先把提示归类：Claude 用不了的几种情况

提示不同，排查的方向差得很远。先对照下表。

| 你看到的情况 | 说明什么 | 下一步 |
| --- | --- | --- |
| 提示所在地区不可用或不受支持 | 出口 IP 不在支持地区，或部分请求没走代理 | 看地区不可用那一节 |
| 收不到登录邮件，或点了链接又回到登录页 | 邮件投递、浏览器环境，或登录过程中换了出口 | 看登录那一节 |
| 能登录，但用一会儿就要求重新验证 | 出口在变化，或浏览器没有保留登录状态 | 看重新验证那一节 |
| 提示账号被限制、暂停 | 账号一侧的规则 | 看账号被限制那一节 |
| 页面一直加载，所有节点表现一致 | 官方故障，或梯子没有连上 | 先做第一步 |
| 网页版能用，命令行或桌面应用不行 | 这些程序没有走代理 | 看命令行和桌面应用那一节 |

整个过程只守一条：一次只改一处，并且用同一个浏览器、同一个账号来对照。

## 第一步：先看官方状态页，再确认梯子在工作

这一步不花时间，却能省掉大量无效操作。

1. 打开 [Claude 状态页](https://status.anthropic.com/)，看有没有进行中的事件。官方故障期间，换节点没有意义。状态页本身也需要通过代理访问。
2. 打开一个与 Claude 无关、需要代理的国外网站。它也打不开，说明是梯子本身没连上，先看[梯子连不上怎么办](/paicha/tizi-lianbushang/)。
3. 状态页显示正常、别的国外网站也能打开，再进入下面的分类排查。

## Claude 地区不可用：对照官方页面查出口 IP

Anthropic 在官网公布了[支持的国家和地区](https://www.anthropic.com/supported-countries)。中国大陆不在其中。别的地区是否受支持会随时调整，请以官方页面当前显示的为准，本文不抄录名单。请遵守所在地法律法规，选梯子不提供法律意见。

提示地区不可用时，要看的是对方收到的来源地址，也就是出口 IP，而不是客户端里显示的节点名。可以这样查：

1. 连上节点，用任何一个会告诉你出口地址和归属地的站点查一下。
2. 记下国家或地区，对照官方列表。
3. 按下表判断：

| 查到的结果 | 说明什么 | 做法 |
| --- | --- | --- |
| 出口不在官方列表内 | 提示是预期结果 | 换到列表内地区的节点，再重新查一次 |
| 出口在列表内，仍然提示 | 部分请求绕过了代理，或 IP 数据库的归属不一致 | 临时切全局模式对照，再换同地区的另一个节点 |
| 查询页显示的是你的本机地址 | 查询页被分流判成了直连，结果不可信 | 先让这个页面走代理，再查 |

出口位于支持地区却仍然提示时，还有一个值得排除的因素：本机网络有 IPv6，而代理只接管了 IPv4，部分请求会从 IPv6 直接发出，服务端看到的就是真实地区。在客户端里关闭 IPv6，或临时关闭本机 IPv6 做对照。节点名不等于出口位置，关于线路结构见[节点地区](/zhinan/jiedian-diqu/)。

手机 App 能否下载，取决于应用商店账号所在地区，以商店页面为准，和节点无关。

## Claude 无法登录：验证邮件与登录页循环怎么查

Claude 的登录方式以当前登录页为准，常见的是邮箱收取登录链接或验证码，以及通过第三方账号登录。按下面的顺序查：

1. **邮件收不到**：先看垃圾邮件和其他分类，确认邮箱地址拼写无误。稍等片刻再重新发送，不要短时间内连续点发送，多封邮件里通常只有最新一封有效，以邮件中的说明为准。
2. **链接打开后回到登录页**：链接可能在邮件客户端的内置浏览器里打开，那里没有你的代理设置和登录状态。把链接复制出来，粘贴到发起登录的那个浏览器中。
3. **链接过期**：登录链接通常有时效，过期后需要重新获取。
4. **不要中途换出口**：从请求邮件、点击链接到完成验证，保持同一个节点。
5. **第三方账号登录**：这条路径会访问对应服务的域名，这些域名同样要走代理。规则模式下漏了域名，常表现为跳转后空白或卡住，排查方法见[ChatGPT 打不开](/paicha/chatgpt-dabukai/)里关于分流规则和 DNS 的一节，原理相通。如果跳转到谷歌后一直弹出验证，见[谷歌验证码](/paicha/google-yanzhengma/)。
6. **浏览器环境**：用无痕窗口或干净的配置文件，暂时关掉扩展，确认没有禁用 Cookie，核对系统时间。

## 登录后很快被要求重新验证：先固定地区和节点

能登录，但用一会儿就被要求重新验证，原因多半在线路和浏览器，而不是账号。

- **出口在变**。“自动选择”“负载均衡”和故障转移类策略组会在后台换节点，每换一次，对服务端来说就是换了一个来源。
- **登录状态没保留**。浏览器设置了关闭时清除 Cookie，或某个扩展定期清理，登录状态每次都会丢。
- **多台设备同时使用**。同一账号在短时间内从不同地区出现，对多数平台是需要额外确认的信号。

处理办法：

1. 为 Claude 单独建一个策略组，手动选定一个节点，用法见[策略组](/jiaocheng/celue-zu/)。
2. 在这个策略组里关闭自动测速切换。故障转移虽然能保住连接，也会换出口，遇到验证问题时先关掉。
3. 尽量让不同设备使用同一个地区的节点。
4. 让浏览器保留这个站点的登录状态。

固定节点后仍然反复验证，再换同地区的另一个节点对照。这是用来定位问题的实验，不是日常使用的做法。

## 账号被限制：只能走官方渠道

提示账号被限制、暂停，或者出现与账号相关的警告，属于平台一侧的规则，与线路无关。这一点需要说得很明确：

- 换节点、换机场、换客户端，都无法改变账号的状态。
- 了解原因和申诉，只能通过 Anthropic 官方帮助中心提供的渠道。
- 不要尝试注册新账号来规避，也不要提供不实信息。

梯子只负责网络连接。账号层面的问题，选梯子无法替你判断，也不提供任何绕过的方法。

## 命令行工具与桌面应用打不开：它们不一定走代理

浏览器能用，不代表所有程序都能用。命令行工具通常不读取系统代理，部分桌面应用也一样，这时表现就是网页版正常、程序里连接超时或提示地区不可用。

处理办法有两种：给终端设置代理环境变量，或者开启 [TUN 模式](/jiaocheng/tun-moshi/)接管整台设备的流量。终端的设置示例：

```bash
export https_proxy=http://127.0.0.1:<端口>
export http_proxy=http://127.0.0.1:<端口>
```

上面的设置只对当前终端会话有效，`<端口>` 以你的客户端显示的混合端口为准。

各工具认的变量名写法并不统一，具体以该工具自己的文档为准。更完整的写法见[终端代理](/jiaocheng/zhongduan-daili/)，AI 编程工具的网络要求见[AI 编程工具用什么梯子](/changjing/ai-biancheng/)。设置完成后，用上面查出口 IP 的方法再确认一次。

## 下一步：按排查结果决定要不要换线路

Claude 用不了的问题，用这个顺序走一遍，通常能帮你定位问题在哪一层：状态页、出口 IP、固定节点、干净的浏览器环境。

- **找到了能用的节点**：固定在一个手动选择的策略组里，记下它的名字。
- **同一家的节点挨个试都不行**：问题可能在这家机场的 IP 质量。选购时需要核对的字段，见[Claude 梯子怎么选](/changjing/claude/)，再到[机场推荐](/tuijian/)里按海外地区筛选。
- **同时在用 ChatGPT**：两家的支持地区以各自官方页面为准，挑一个都在列表内的地区，可以少切换一次。
- **还没想清楚预算和设备数**：用[选梯子向导](/gongju/xuan-tizi-xiangdao/)先定下来。
