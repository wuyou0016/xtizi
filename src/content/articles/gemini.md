Gemini 梯子要先分清入口：一边是网页和手机上的 Gemini 应用，另一边是面向开发者的 Gemini API 与 Google AI Studio。Google 为这两类入口分别公布了可用地区页面，规则不一定相同，所以挑节点之前得先知道自己该对照哪一张表。此外 Gemini 还比其他 AI 工具多一层变量：你的 Google 账号。

## 谷歌 Gemini 有两张可用地区表，先确认对照哪一张

| 入口 | 对照的官方页面 | 流量从哪里发出 | 常见卡点 |
| --- | --- | --- | --- |
| Gemini 网页版 | Gemini 应用可用地区 | 浏览器 | 出口地区、账号条件、分流漏了域名 |
| Gemini 手机应用 | Gemini 应用可用地区 | App 自身 | 应用商店地区、手机客户端后台被关 |
| Google AI Studio | Gemini API 可用地区 | 浏览器 | 出口地区 |
| Gemini API | Gemini API 可用地区 | 你的代码或终端 | 出口地区、终端没有走代理 |

两个页面分别是[Gemini 应用可用地区](https://support.google.com/gemini/answer/13575153)和[Gemini API 可用地区](https://ai.google.dev/gemini-api/docs/available-regions)。中国大陆在两张表里都没有出现。其余地区是否可用、两张表是否一致，以官方页面当前内容为准，选梯子不另列名单。

这带来一个实际后果：某个地区的节点能打开 Gemini 应用，不代表用它调 API 也行，反过来也一样。如果你两种都用，就要找一个在两张表里都出现的地区。请遵守所在地法律法规，选梯子不提供法律意见。

## 出口 IP 和 Google 账号，各管什么

很多人把所有问题都归到节点上，其实 Google 判断你能不能用，看的不止一个信号。

- **出口 IP**：回答“你现在在哪里”。这是梯子能改变的部分，换节点就是换这个。
- **账号关联的国家或地区**：Google 会给账号关联一个国家或地区，用来确定适用的条款和可用的服务。这个关联由 Google 根据多种信息判定，细则没有公开，以 Google 官方说明为准。梯子改变不了它。
- **账号本身的条件**：官方可用地区页面同时列出了对账号类型、年龄等方面的要求。公司或学校的账号是否能用，还取决于管理员有没有开放。

所以排查时要分两层：先确认网络侧的出口没有问题，再看账号侧。网络侧可以自己验证，账号侧只能按官方规则来，本文不提供任何修改或伪装账号信息的做法。

还有一个 Google 特有的现象值得知道：同一个 IP，在不同的归属地数据库里可能被标成不同地区。你在第三方页面查到的结果，不一定等于 Google 自己的判断。Google 用的是它自己的数据，所以会出现“节点名和查询结果都是甲地，Google 却按乙地处理”的情况。这不是你设置错了，而是这个 IP 段在 Google 那里的归属就是如此，只能换节点。

## Gemini 节点怎么选：地区在表内、少被滥用、长期固定

挑 Gemini 梯子的节点，按下面的顺序筛。

1. **出口地区在你所用入口的官方列表内**。这是硬条件，其余都排在它后面。
2. **Google 对这个 IP 的判断与预期一致**。方法在后面的验证一节，核心是看 Google 自己的页面怎么显示你的位置。
3. **IP 没有被大量滥用**。同一个出口上请求太多时，Google 会频繁弹出验证，搜索、登录和 Gemini 都会受影响。识别方法见[谷歌验证码](/paicha/google-yanzhengma/)。
4. **同地区有替补**。一个地区只有一个节点，它出问题时你只能换地区，而登录地点频繁变化对 Google 账号来说通常是异常信号。
5. **距离和延迟**。排在后面。Gemini 以文字交互为主，延迟高一些只是多等片刻。各地区节点的一般特点见[节点地区](/zhinan/jiedian-diqu/)。

Gemini 和 Google 搜索、Gmail 用的是同一个账号体系，建议让这几项服务走同一个出口。具体到搜索和邮箱的网络要求，可以看[谷歌梯子](/changjing/google/)那篇。如果你还同时在用其他 AI 工具，[ChatGPT 梯子](/changjing/chatgpt/)和[Claude 梯子](/changjing/claude/)各自对照的是另外两家的官方列表，三者交集里的地区用起来省心。

## “所在地区不支持”的五个排查方向

看到这类提示，先别急着下结论，按从易到难的顺序看。

1. **出口地区本身不在列表内**。查当前出口 IP 的归属地，对照你所用入口的那张官方表。
2. **部分请求没有走代理**。规则模式下，如果规则集没有覆盖 Gemini 用到的全部域名，一部分请求会直连，Google 就看到了你的真实位置。临时切到全局模式对比一次，就能判断是不是这个原因。规则怎么补，见[分流规则](/jiaocheng/fenliu-guize/)。
3. **DNS 暴露了位置**。域名解析请求如果没有经过代理，也可能成为判断依据之一。检查方法见[DNS 泄漏](/paicha/dns-xielou/)。
4. **Google 对 IP 的地区判断与节点名不符**。换同地区的另一个节点，或者换一个地区再试。
5. **账号侧条件不满足**。用另一个 Google 账号在相同节点下对比。一个能用一个不能用，问题就在账号，不在线路。

API 用户还有一个高频原因：终端和脚本不一定理会系统代理，请求直接从本机网络发出。浏览器里的 AI Studio 能打开，代码却报地区错误，多半是这个情况。设置方法见[终端代理](/jiaocheng/zhongduan-daili/)。

## 挑 Gemini 机场时，套餐页该看的字段

选梯子没有任何机场访问 Gemini 的测试数据，下表只说明每个字段该怎么读。

| 套餐页字段 | 对 Gemini 的意义 | 读的时候注意 |
| --- | --- | --- |
| 节点地区列表 | 决定能不能用 | 对照官方地区页面，关注同一地区的节点数量 |
| 线路类型 | 影响连接稳定性 | 属于商家自述，连上后自己观察是否经常断 |
| 出口 IP 说明 | 影响验证频率 | 写了“原生”之类的词，要看有没有说明范围和核对办法 |
| 月流量 | 影响很小 | 文字对话耗流量少，不必为此买大套餐 |
| 付费周期 | 影响试错成本 | 优先月付或有试用，先验证再续 |
| 设备数 | 看你有几台设备 | 手机和电脑都用时，确认能同时在线 |

读这张表时把顺序记住：地区第一，稳定第二，价格和流量靠后。

## 自己核对：从出口 IP 到账号的检查顺序

下面这套步骤不依赖任何第三方结论，都是你自己能看到的现象。

1. 连上准备长期使用的节点，用任意 IP 查询页面记下出口 IP 和归属地。
2. 打开 Google 搜索，随便搜一个词，看结果页底部显示的所在地区（以当前页面显示为准）。这是 Google 自己对你位置的判断，比第三方查询更接近 Gemini 实际用到的结果。
3. 把第 2 步看到的地区，对照官方的 Gemini 应用可用地区页面；用 API 的，对照 API 可用地区页面。
4. 打开 Gemini，登录后发一条消息，确认能正常返回，而不是只看首页能不能打开。
5. 让它输出一段较长的内容，观察是否中途停住，以此判断线路稳不稳。
6. 隔一两天重复第 1、2 步，确认出口没有悄悄变到别的地区。

第 2 步显示的地区和节点名对不上时，以 Google 显示的为准，换节点。第 4 步失败而前三步都正常时，换一个 Google 账号对比，区分是账号侧还是网络侧。

## 下一步：先定入口和地区，再去挑套餐

选 Gemini 梯子的顺序是入口、地区、套餐，不要反过来从价格开始挑。

- 只用 Gemini 应用聊天的人：打开应用可用地区页面选定一个地区，然后到[机场推荐](/tuijian/)里找资料记录了该地区节点、可以月付的套餐。
- 要调 API 的开发者：对照 API 可用地区页面选地区，并先把终端代理或 TUN 配好，再测线路。
- 不确定预算和设备数怎么定：先用[选梯子向导](/gongju/xuan-tizi-xiangdao/)过一遍。
- 已经在用、突然不行了：按上面五个排查方向走一遍，大多数情况不需要换机场。
