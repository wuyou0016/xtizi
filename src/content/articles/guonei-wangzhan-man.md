开梯子国内网站变慢，通常是因为国内流量也被送去了海外节点，也就是分流没有生效。常见原因就几个：模式停在全局、规则集不全或过期、DNS 把国内域名带到了海外 CDN，以及 TUN 模式下规则和 DNS 对不上。判断的办法很直接，看客户端的连接记录里，这个国内域名命中了哪条规则、走了哪条出口。

## 先对号入座：国内网站走代理的几种表现

不同表现指向不同位置，先看自己属于哪一种。

| 现象 | 说明什么 | 下一步 |
| --- | --- | --- |
| 国内网站整体变慢，关掉梯子就恢复 | 国内流量绕了海外节点 | 先做第一步查模式，再做第二步查连接记录 |
| 国内视频提示地区不可用或内容受限 | 对方看到的访问来源是海外出口 | 同上，这是国内流量走代理的典型副作用 |
| 切到直连模式变快，回到规则模式又慢 | 规则没有覆盖这个域名，落到了默认策略 | 做第二步、第三步 |
| 规则模式正常，打开 TUN 以后变慢 | TUN 下拿不到域名，规则对不上 | 做第五步 |
| 直连了，目标地址却是海外的 | DNS 把域名解析到了海外地址 | 做第四步 |
| 只有某个 App 慢，浏览器访问国内站正常 | 该 App 用 IP 直连，或用了另一批域名 | 在连接记录里看这个 App 的目标 |

原则只有一条：一次只改一处。改完要关闭网页或 App 再重新打开，旧连接会沿用旧的路径，不重开看不出效果。

## 第一步：确认模式没有停在全局

全局模式会把所有流量送到你选中的那个节点，国内网站也不例外。规则模式才会按规则判断谁走代理、谁直连。三种模式的区别见[规则模式、全局模式、直连模式](/jiaocheng/guize-quanju-zhilian/)。

1. 打开客户端主界面，找到出站模式的切换处。
2. 如果当前是全局，切回规则模式，关掉并重新打开那个慢的国内网站。
3. 如果本来就是规则模式，临时切到直连，再打开同一个网站对照。

第三步的结果很有信息量。直连后明显变快，说明变慢和代理路径有关，继续往下查；直连后依然很慢，问题在你的本地网络或目标网站，不在梯子，换节点、改规则都不会有用。对照完记得切回规则模式。

## 第二步：看连接记录，确认这个域名走了哪条策略

这一步是整篇文章的核心。大多数客户端都有一个“连接”页面，实时列出每一条连接的目标地址、命中的规则和走的出口，名称略有差异，含义相同。

1. 在连接页先清空记录，或者暂停刷新。
2. 打开那个慢的国内网站。
3. 在列表里按关键词搜到它的域名。
4. 记下它的“规则”和“链路”两列。

| 链路 | 规则 | 说明什么 | 下一步 |
| --- | --- | --- | --- |
| 直连 | 国内相关的规则 | 分流生效了，慢不是梯子造成的 | 查本地网络和目标站点 |
| 某个节点或策略组 | 最后的兜底规则 | 没有任何规则覆盖它，落到了默认策略 | 做第三步，补规则或更新规则集 |
| 某个节点或策略组 | 明确的代理规则 | 规则把它指向了代理，可能是分类有误或顺序靠前 | 检查规则顺序和自定义规则 |
| 目标只有 IP，没有域名 | 无域名可匹配 | 客户端没有拿到域名，域名规则匹配不上 | 做第四步、第五步 |

规则是从上往下逐条匹配的，命中即停。所以一条过宽的代理规则放在前面，会把后面的国内直连规则架空。

## 第三步：规则不全或过期，分流不生效最常见的位置

规则集和地理数据库需要更新，订阅里自带的规则也可能本来就不完整。按下面的顺序处理：

1. 更新订阅配置，再更新规则集和地理数据库。客户端里一般有对应的更新按钮。
2. 检查配置里是否同时有两类规则：国内域名直连、国内 IP 直连。只有节点、没有规则的订阅，需要靠客户端的覆写或规则功能套用一份直连规则。
3. 只有个别域名漏网时，加一条自定义规则，位置放在兜底规则之前。

```yaml
rules:
  - DOMAIN-SUFFIX,example.cn,DIRECT
  # example.cn 换成你在连接页里看到的国内域名
  # 放在兜底规则之前，写法以你所用内核的文档为准
```

不要大批量手抄域名。规则集由维护者持续更新，比手写可靠，自己只补个别漏网的。规则怎么写、怎么组织，见[分流规则](/jiaocheng/fenliu-guize/)，各项语法可对照[Mihomo（Clash Meta）文档](https://wiki.metacubex.one/)。

## 第四步：DNS 把国内域名带去了海外，开梯子国内网站变慢的隐蔽原因

访问网站前，域名要先解析成 IP。许多大型网站会按“谁在查询”返回就近的 CDN 地址。如果你的 DNS 查询经过海外节点，或者用的是只能从海外访问的 DNS 服务，国内域名可能被解析到海外或绕路的地址。这时即使规则判定直连，连接的也是一个远处的地址，当然慢。

怎么发现：连接页里该域名显示为直连，却能看到目标 IP 的归属地在海外。可以把这个 IP 放到任意地址归属查询页面里看一下。

怎么处理：

- 让国内域名使用国内可直接访问的 DNS 解析，海外域名再走海外 DNS。客户端的 DNS 设置里通常有按域名分流的选项，原理和设置见 [Clash DNS](/jiaocheng/clash-dns/)。
- 使用 fake-ip 时，把国内常用域名加入不使用 fake-ip 的名单，是否需要以你的客户端和规则为准。
- 不要同时开着浏览器自带的加密 DNS 和客户端的 DNS 分流，两处各管一半，结果很难预测。先关掉浏览器那一份对照。

DNS 改动的影响面比规则大，改一处就验证一次。

## 第五步：TUN 模式下规则与 DNS 不匹配

[TUN 模式](/jiaocheng/tun-moshi/)会接管整台设备的流量，连不读取系统代理的程序也包括在内。代价是：数据到达内核时往往已经是 IP，域名信息可能丢失。客户端只看到一个 IP，域名规则就无法命中，只能落到按 IP 判断的规则或兜底规则上，国内站点因此被送去代理。

处理顺序：

1. 确认 TUN 的 DNS 劫持选项已开启，让域名查询回到客户端自己处理。
2. 开启域名嗅探，让内核能从连接内容里还原出域名。
3. 检查系统或浏览器是否绕开了客户端的 DNS，比如应用自带加密 DNS。
4. 对照实验：关掉 TUN，改回[系统代理](/jiaocheng/xitong-daili/)，同一个网站是否恢复正常。恢复了，说明问题就在 TUN 与 DNS 的配合上。

两种方式的适用场景不同，不必为了解决这个问题一直开着 TUN。

## 国内 App 打不开：分应用代理与拒绝运行

手机上，国内 App 慢或打不开，多半是它被拉进了 VPN 通道。如果客户端有分应用代理功能，把这类 App 设为不走代理，是最直接的办法。设置方法可参考[v2rayNG 安卓教程](/jiaocheng/v2rayng-android/)里的分应用部分，其他客户端的入口名称各不相同。

另一种情况和分流无关：部分 App，尤其是金融和支付类，检测到系统里有代理或 VPN 在运行，就会拒绝使用。这是对方的安全策略，不是你设置错了。梯子无法解决，只能在使用这些 App 时暂时关闭梯子。

## 改完先确认，再把分流固定下来

想确认开梯子国内网站变慢已经修好，国内外两个方向都要看：

1. 关闭并重新打开那个国内网站，连接页里应命中直连规则。
2. 目标 IP 的归属在国内。
3. 再打开一个国外网站，连接页里应走节点，没有被误判成直连。
4. 隔一天再看一次。规则集更新之后，旧问题可能重现，也可能改善。

接下来按你的情况选择：

- **想弄懂规则怎么写**：从[分流规则](/jiaocheng/fenliu-guize/)开始，自己维护比依赖订阅里的模板更可控。
- **规则和 DNS 都正确仍然很慢**：问题可能在线路本身，转到[梯子速度慢](/paicha/tizi-sudu-man/)按段定位。
- **订阅的规则一直不完整**：下次选购时重点看订阅格式和规则支持，可参考[Clash 机场怎么选](/zhinan/clash-jichang/)，再到[机场推荐](/tuijian/)里筛选。
- **还没想清楚自己要什么**：用[选梯子向导](/gongju/xuan-tizi-xiangdao/)回答几个问题。

页面底部的机场数据块只是缩小候选范围的参考。里面的机场是否带有完整的国内直连规则，需要你拿到订阅后，按上面的连接记录方法自己核对。
