同一个节点，上午能看，晚上提示“正在使用代理”，隔天又恢复，这不是错觉，也不一定是节点坏了。流媒体解锁并不是节点的一个固定属性，而是三个条件同时成立时的结果，任何一个条件变化，结果都会变。下面先讲清这三个条件，再讲平台怎么识别代理，最后教你自己验证。

## 流媒体解锁是什么意思：三个条件同时成立

“解锁”是梯子圈的说法，平台不会这样称呼。拆开看，它至少包含三个条件：

| 条件 | 它的含义 | 谁说了算 | 你能否直接控制 |
| --- | --- | --- | --- |
| 出口 IP 被当作普通用户 | 平台没有把节点的出口识别为代理或机房流量 | 平台 | 不能，只能选择和验证 |
| 内容在该地区有授权 | 你想看的节目在这个地区的内容库里 | 平台与版权方 | 不能，可以查官方说明 |
| 账号信息与地区相符 | 账号的注册地、付款方式、订阅方案与地区匹配 | 平台 | 部分，涉及你自己的账号 |

所以“解锁了”其实是一句描述当时状态的话，解锁流媒体不是一次设置完就永远有效的事：此时此刻，这个节点的出口通过了平台的判断，这个地区有你想看的内容，账号也没有触发限制。

这也解释了一个常见误会。很多人以为选一个标着“解锁”的节点就万事大吉，但如果你想看的内容在这个地区根本没有授权，再好的节点也无济于事。内容库的地区差异，可以在 Netflix 帮助中心的[各地区提供情况](https://help.netflix.com/en/node/14164)页面看到概况，Disney+ 的相关规则则以其[帮助中心](https://help.disneyplus.com/)为准。

## 平台怎么发现你在用代理：四类常见依据

平台不公开具体的判断规则，也会不断调整。下面是一般性的归类，用来帮你理解现象，不是规则清单。

1. **IP 本身的信息。** 出口 IP 属于家庭宽带还是机房，地理信息登记在哪里，是否出现在已知的代理或滥用名单里。这部分在[原生 IP](/zhinan/yuansheng-ip/)一文里有详细解释。
2. **同一个 IP 上的账号情况。** 一个出口地址上同时有大量不同账号登录，平台看到的是异常的集中度。节点被越多人共用，这个信号越明显。
3. **地区信号是否自洽。** 出口 IP 在一个地区，而 DNS 解析仍然由本地运营商完成，或者设备的时区、语言等信息与出口地区明显不一致，平台可能会觉得矛盾。其中 DNS 这一项，往往是配置问题造成的，排查方法见[DNS 泄漏](/paicha/dns-xielou/)。
4. **账号与设备信息。** 账号注册地、付款方式、过往的登录地区，以及设备的变化。这一项和节点无关，是账号自身的状态。

前三项与网络有关，第四项与账号有关。排查时要分开看，避免把账号问题归因给节点，或反过来。

## 为什么同一个解锁节点的流媒体解锁时灵时不灵

理解了上面的依据，“时灵时不灵”就不难解释。下表把常见原因放在一起：

| 现象 | 可能的原因 | 你能验证吗 |
| --- | --- | --- |
| 昨天能看，今天提示代理 | 平台更新了名单，出口 IP 被收录 | 难，可以换节点对照 |
| 白天正常，晚上异常 | 晚间同一出口的使用人数增加 | 部分，多个时段对照 |
| 同一节点，每次连接结果不同 | 节点背后有多个出口或负载均衡，每次落在不同地址上 | 可以，记录每次的出口 IP |
| 登录能看，播放失败 | 登录和播放走了不同的请求，其中一部分没走代理 | 可以，检查分流与 DNS |
| 同一个账号在不同设备结果不同 | 设备所处网络、客户端设置不同 | 可以，逐台对比 |
| 规则没变但突然不行了 | 平台调整了识别方式 | 不能 |

第三行值得单独说。不少机场的节点背后不是一个出口，而是一组出口，每次连接可能落在不同的地址上。其中某些地址已被平台标记，另一些没有，于是你会觉得“有时能用，有时不能”。这种情形在节点名称上完全看不出来，只能靠记录每次的出口 IP 来发现。

第四行则属于配置问题：代理客户端的分流规则或 DNS 设置让一部分流量走了直连。这类问题的整体排查，可以参考[分流规则](/jiaocheng/fenliu-guize/)。

## 只能看自制剧：内容库和代理提示之间的关系

有一种现象很典型：Netflix 自己制作的节目可以播放，其他节目却提示无法观看，或者弹出代理提示。

Netflix 帮助中心的[官方说明页](https://help.netflix.com/en/node/277)写明了背景：设备或网络被识别为 VPN 或代理时会出现提示，官方建议关闭后重试。页面没有描述“只剩自制剧”这种现象，它是用户常见的说法：自制内容往往在多个地区同时拥有授权，所以有时成为“仍然能看”的那一部分，受地区限制的内容则播放不了。

这对你有两个启示：

- 能播放一部自制剧，**不能**证明这个节点已经“解锁”。要验证，应当选一部只在目标地区提供的内容来试。
- 如果出现了这种“只能看自制”的状态，通常说明平台已经把当前出口识别为代理。继续换节点之前，先看[Netflix 提示正在使用代理怎么办](/paicha/netflix-daili-tishi/)，了解原因和可行做法。

各平台在这方面的做法不同。每个平台的具体规则，请以它自己的帮助页面为准。[奈飞梯子场景页](/changjing/netflix/)和[Disney+ 梯子场景页](/changjing/disney-plus/)分别整理了这两个平台的地区库与代理提示要点。

## 解锁节点和流媒体机场的宣传，怎么读

套餐页上的“解锁”相关字样，可以按下面的方式翻译。

| 宣传词 | 更合理的理解 | 可以追问 |
| --- | --- | --- |
| “解锁 Netflix”“解锁 Disney+” | 在某个时刻，某些节点通过了平台的判断 | 哪些节点，检测的时间和频率 |
| “全解锁” | 对多个平台都有宣称 | 有没有逐个平台的说明与更新记录 |
| “流媒体专用节点” | 服务商划出一批节点用于流媒体 | 是否独享出口，共用人数如何控制 |
| “每日检测” | 服务商有自己的检测 | 检测方法和结果是否对用户公开 |
| 流媒体机场 | 自称针对流媒体做优化的机场 | 优化的具体做法是什么 |

“流媒体机场”不是一个严格的类别，没有统一标准。选梯子目前没有任何自己的解锁测试数据，页面上的数据块只整理服务商公开的资料，例如覆盖的地区、节点说明和支持的客户端。它能帮你缩小范围，不能替你回答“现在能不能看”。

使用任何平台，都要遵守平台条款，也请遵守所在地法律法规，选梯子不提供法律意见。

## 怎么自己验证解锁流媒体是否真的可用

验证的原则是：用你自己的网络，在你要看的内容上，多次重复，并且记录。

1. **先查内容在目标地区有没有授权。** 用平台的官方说明确认，避免白白浪费时间。
2. **连上节点，核对出口。** 用 IP 查询页确认出口国家，与节点标注对一下。
3. **选一部目标地区独有的内容。** 不要拿自制内容来测。
4. **观察结果。** 能正常播放、能播放但内容库缩水、提示代理，三种结果要分开记。
5. **换条件重复。** 换时段、换节点、换网络，各试几次。
6. **记录。** 下面是一份可以直接照抄的记录表。

| 记录项 | 第一次 | 第二次 | 第三次 |
| --- | --- | --- | --- |
| 日期与时段 | 填写 | 填写 | 填写 |
| 使用的节点 | 填写 | 填写 | 填写 |
| 出口 IP 国家 | 填写 | 填写 | 填写 |
| 测试的内容 | 填写 | 填写 | 填写 |
| 结果与提示 | 填写 | 填写 | 填写 |

得到记录后，这样解读：

| 记录里的规律 | 说明什么 | 下一步 |
| --- | --- | --- |
| 同一节点，不同时段结果不同 | 状态会变化，不能一次定论 | 多测几个时段再判断 |
| 同一节点，出口 IP 每次不同 | 背后是多出口 | 向服务商确认出口数量与管理方式 |
| 所有节点都提示代理 | 可能是客户端配置问题 | 检查 DNS 与分流 |
| 换网络后结果变好 | 与你当前网络有关 | 以实际使用的网络为准 |

遇到提示代理时，有三件事不要急着做：不要连续频繁登录、登出；不要在多个节点之间快速反复切换；不要把一两次失败当成服务商的责任。先查配置，再换节点。

## 现在可以做的三步

1. **先确认内容。** 到平台官方页面确认你想看的内容在哪个地区有授权，再决定选哪个节点地区。地区的取舍见[节点地区](/zhinan/jiedian-diqu/)。
2. **把验证做成习惯。** 买短周期套餐，用上面的记录表测几天，再决定是否续费。
3. **按需筛选机场。** 想看哪些机场公开了覆盖地区和流媒体相关资料，可以到[梯子推荐](/tuijian/)；想把预算和用途一起考虑，用[选梯子向导](/gongju/xuan-tizi-xiangdao/)。

流媒体解锁是一种会随时间变化的状态，不是一次买断的能力。接受这一点，反而能少走很多弯路。
