faqs:
  - q: 自动选择和故障转移有什么区别？
    a: 自动选择会定期测试组内所有节点，挑当前延迟较低的使用，所以会比较频繁地换节点。故障转移则按列表顺序优先使用靠前的节点，只在它不可用时才切到后面的节点，平时更稳定，出口变化也更少。
  - q: 负载均衡能把网速叠加起来吗？
    a: 不能简单理解成叠加。它把不同的连接分散到不同节点，但单条连接仍然只走一个节点，所以单线程下载不会因此变快。它也会让你的出口地址频繁变化，对账号类服务不友好。多数个人用户不需要它。

策略组怎么用？一句话说清：它把一批节点包装成一个“选择器”，规则只需要把流量交给这个选择器，至于最后用哪个节点，由选择器的类型决定。手选组由你点，自动选择组按测试结果挑，故障转移组在当前节点失效时换，负载均衡组把连接分散开。没有哪一种适合所有场景，选错类型，轻则出口来回跳，重则账号被要求反复验证。

## 策略组是什么：规则与节点之间的选择器

如果没有策略组，规则只能直接写“这个网站走节点一”。节点一一旦失效，你就得去改每一条规则。有了策略组，规则写成“这个网站走代理选择”，节点怎么挑是策略组自己的事，换节点时规则一个字都不用动。

所以它做的是两件事：

- **打包：** 把一批节点收进一个名字下，规则引用名字即可。
- **决策：** 按类型自己的逻辑，在组内的节点里选出当前使用的那个。

策略组还能互相嵌套：一个组里可以放节点，也可以放其他组，以及 `DIRECT`（直连）。你在客户端“代理”页面里看到的那些按钮和下拉框，就是一个个策略组。词典里有简短的解释：[策略组](/cidian/celue-zu/)。与规则的关系，可以在[分流规则怎么写](/jiaocheng/fenliu-guize/)里看，规则的最后一个字段，往往就是一个策略组的名字。

## 自动选择、故障转移、负载均衡：四类策略组怎么选

下表以 Mihomo 系配置中常见的四种类型为准，类型全集以官方文档为准：

| 类型 | 配置里的写法 | 怎么选节点 | 适合 | 不适合 |
| --- | --- | --- | --- | --- |
| 手选 | select | 你自己点，选哪个用哪个 | 对出口有要求的服务，如 AI、账号类 | 想完全不管的人 |
| 自动选择 | url-test | 定期测试，选延迟较低的 | 日常刷网页，图省心 | 需要固定出口地址的服务 |
| 故障转移 | fallback | 按列表顺序优先用靠前的，不可用才切后面 | 想要稳定、少换节点，同时有备用 | 想总是用延迟最低的 |
| 负载均衡 | load-balance | 把不同连接分散到多个节点 | 同时开很多连接的场景，如批量下载 | 账号类服务，因为出口会变 |

如果你是：

- **刚上手、只想省事的人：** 日常用故障转移或自动选择，遇到问题再手选。
- **用 AI、社交、支付等账号类服务的人：** 这类服务单独用手选，固定一个节点。
- **常做多任务下载的人：** 再考虑负载均衡，但要接受出口地址不固定。

自动选择依据的是延迟数字，而延迟只是线路好坏的一个侧面，不等于带宽，也会随时间波动，原理见[节点测速怎么看](/jiaocheng/jiedian-cesu/)。所以自动选择选出来的节点，不一定是你体感最好的。

## 各类型的策略组在配置里长什么样

下面是只展示结构的示意，节点名和测试地址都是占位，间隔、容差等数值以你的需要和官方文档为准：

```yaml
proxy-groups:
  - name: 代理选择
    type: select
    proxies: [自动选择, 故障转移, 节点一, 节点二, DIRECT]

  - name: 自动选择
    type: url-test
    proxies: [节点一, 节点二, 节点三]
    url: "https://test.example.com/"
    interval: 间隔秒数
    tolerance: 容差值

  - name: 故障转移
    type: fallback
    proxies: [节点一, 节点二, 节点三]
    url: "https://test.example.com/"
    interval: 间隔秒数

  - name: 均衡组
    type: load-balance
    proxies: [节点一, 节点二, 节点三]
    url: "https://test.example.com/"
    interval: 间隔秒数
    strategy: 策略名
```

几个字段的含义，读懂就够了：

- **proxies**：组里包含的成员，可以是节点，也可以是别的组。
- **url 和 interval**：用哪个地址、隔多久测试一轮，自动选择和故障转移靠它判断节点是否可用。
- **tolerance**：自动选择里的容差，新节点要比当前节点好出一定幅度才会切换，避免来回抖动。
- **strategy**：负载均衡的分配方式，可选值以官方文档为准。

最外层的“代理选择”是一个手选组，里面放了另外两个组和几个节点，这是机场配置里常见的结构：你在顶层点一下，就能决定走自动、走故障转移，还是直接固定某个节点。字段说明见 [Mihomo 官方文档](https://wiki.metacubex.one/)。

## 为什么 AI 与账号类服务不适合自动选择和负载均衡

这类服务有一个共同点：它们会观察你登录时的网络环境，环境变化太频繁，就可能触发额外验证、退出登录，甚至限制账号。而自动选择和负载均衡恰恰会让出口地址变化：

| 类型 | 出口为什么会变 | 对账号类服务的影响 |
| --- | --- | --- |
| 自动选择 | 每轮测试后可能换到另一个延迟更低的节点 | 同一个会话中出口地址可能跳变 |
| 负载均衡 | 不同连接被分到不同节点 | 同一时刻就有多个出口地址 |
| 故障转移 | 只有当前节点失效才换 | 变化少，但失效时仍会换 |
| 手选 | 只有你自己改才会变 | 最可控 |

所以建议是：**对出口敏感的服务，手选并固定一个节点。** 具体某项服务该选哪个地区，不在本文范围，可以看[ChatGPT 梯子怎么选](/changjing/chatgpt/)，那里讲的是节点地区和常见报错。如果某项服务时好时坏，先查一下出口是不是换过，再去怀疑别的原因。

## 给特定服务单独建一个固定节点的组

做法分三步，思路是：新建一个手选组，把它放进规则里。

1. **新建组。** 在客户端的覆写或合并功能里，或在配置里，新增一个手选组，成员只放你要固定的那一个节点，也可以再放一个备用节点。
2. **加规则。** 在规则里，把这项服务的域名指向这个组，并且放在更宽泛的规则之前：

```yaml
proxy-groups:
  - name: 固定节点组
    type: select
    proxies: [节点二]

rules:
  - DOMAIN-SUFFIX,example.com,固定节点组
  - MATCH,代理选择
```

3. **保存并重新加载配置。** 在代理页面应该能看到多出了“固定节点组”。

这里 `example.com` 是占位域名，你要写的是自己那项服务的真实域名，可以在客户端连接页面里找到。规则的顺序和写法，参考[分流规则怎么写](/jiaocheng/fenliu-guize/)。别忘了，用这个组的前提是处于规则模式，选法见[Clash 规则模式、全局模式、直连模式怎么选](/jiaocheng/guize-quanju-zhilian/)。

## 怎么确认策略组按预期工作

建好组之后，不要想当然，逐项核对：

1. **看代理页面。** 每个组下应当显示当前选中的成员。手选组就是你点的那个，自动选择和故障转移组显示的是内核当前在用的那个。
2. **先做一轮延迟测试，再看自动选择。** 测完后，组里选中的节点应当是延迟较低的那一批之一。如果选中项明显不是，检查 `url` 是否可用。
3. **到连接页面看链路。** 访问你为固定节点组写了规则的网站，连接记录里应该显示：命中了你的规则，经过“固定节点组”，最后落到你选的节点。
4. **看出口有没有变。** 多次刷新、间隔一段时间后再访问，检查出口地址是否保持不变。固定组的出口应当稳定。
5. **更新订阅后回来看一眼。** 节点改名或被移除，选择可能被重置。

如果规则没命中你的组，先排查顺序和名字是否一字不差，而不是怀疑策略组。

## 几个常见误区

| 误区 | 事实 |
| --- | --- |
| 自动选择一定选到最适合我的节点 | 它只依据测试地址上的延迟，不等于带宽，也不等于出口地区适合 |
| 负载均衡能叠加多个节点的速度 | 它分散的是连接，单个连接仍只走一个节点 |
| 故障转移会一直选延迟最低的 | 它优先用靠前的成员，只在不可用时才换 |
| 策略组的名字随便写，大概对得上就行 | 规则里引用的名字必须和定义逐字一致 |
| 所有服务都该走同一个组 | 对出口敏感的服务，应当单独建组固定节点 |

## 下一步：先看现有的组，再按需调整

1. 打开客户端的代理页面，把现有的策略组从上到下看一遍，对照上面的类型表，认出它们各自是什么类型。
2. 日常保持原样用着，只为出口敏感的服务单独建一个固定节点的组。
3. 想要验证节点好坏，先看[节点测速怎么看](/jiaocheng/jiedian-cesu/)，再决定要不要用自动选择。
4. 节点本身不够好或需要换线路，到[梯子推荐](/tuijian/)按用途筛选候选，并在下单前自己核对退款规则。
