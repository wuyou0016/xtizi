faqs:
  - q: Ubuntu 上装梯子选 deb 还是 AppImage？
    a: 优先选 deb。它由系统的包管理器安装，依赖会一并处理，卸载和升级也有统一入口。AppImage 是单个可执行文件，不依赖发行版，适合临时试用或者没有对应安装包的发行版，但桌面集成和自动更新要自己处理。两者功能相同，区别在管理方式。
  - q: 没有图形界面的 Linux 服务器怎么用梯子？
    a: 用内核加配置文件。从官方仓库发布页下载与机器架构对应的 Mihomo 或 sing-box 内核，把机场订阅保存为配置文件，先在前台运行确认日志正常，再写一个 systemd 服务让它开机启动、异常时自动重启。服务文件的写法以两个项目的官方文档为准。
  - q: 设置了环境变量，为什么有的命令还是不走代理？
    a: 代理环境变量只对会读取它的程序生效，而且只在设置它的那个终端会话里有效。使用 sudo 执行的命令、由 systemd 启动的服务、Docker 守护进程默认都不继承你在终端里设置的变量，需要各自单独配置。想让所有程序都走代理，要改用 TUN 模式。
  - q: 云服务器上跑代理内核要注意什么？
    a: 注意监听地址。带公网 IP 的机器如果让代理端口或控制面板端口监听在所有网卡上，又没有防火墙限制，就等于把代理开放给了整个互联网，可能被他人滥用并消耗你的流量。只给本机用时，让端口只监听本地回环地址，控制面板设置访问密钥。
  - q: 发行版软件源或 AUR 里的同名包可以装吗？
    a: 那些是社区维护者打包的版本，不是项目官方发布的构建。它们通常是从官方源码或官方二进制重新打包，装起来方便，但维护者是谁、更新是否及时需要你自己判断。对来源要求严格时，直接用官方仓库发布页的文件，并核对校验值。

Linux 梯子下载分两条路：有桌面环境的机器装图形客户端，服务器和无界面的机器用内核加配置文件。两条路用的内核是同一批，差别在有没有人替你把配置、启动和系统代理这些事包装成按钮。页面顶部的数据表列出了本站收录的、支持 Linux 的工具及其官方地址，下面讲怎么在其中选、安装包格式怎么挑、常驻运行和终端代理怎么处理。

| Clash Verge Rev | 图形客户端 | Mihomo | 导入 Clash 订阅 | 桌面日常使用 | 低 |
| Clash Party | 图形客户端 | Mihomo | 导入 Clash 订阅，支持覆写 | 桌面使用，想改配置 | 中 |
| FlClash | 图形客户端 | Mihomo | 导入 Clash 订阅 | 桌面使用，手机上也用同一款 | 低 |
| Clash Nyanpasu | 图形客户端 | Mihomo | 导入 Clash 订阅 | 桌面使用 | 中 |
| v2rayN | 图形客户端 | Xray / sing-box | 通用订阅、分享链接 | 桌面使用，机场给的是通用订阅 | 中 |

选择路径很直接：

- 日常用的笔记本或台式机，有 GNOME、KDE 这类桌面：选图形客户端。机场给 Clash 订阅就从 [Clash Verge Rev 下载](/xiazai/clash-verge-rev/) 看起，给通用订阅就看 [v2rayN 下载](/xiazai/v2rayn/)。
- 云服务器、家里的小主机、只通过 SSH 登录的机器：直接用内核，见 [Mihomo 下载](/xiazai/mihomo/) 与 [sing-box 下载](/xiazai/sing-box/)。
- 桌面机器但只想让终端里的开发工具走代理：图形客户端加环境变量就够，不必折腾内核。

图形客户端其实也是在后台运行同一个内核，所以两条路的订阅和规则是通用的。

## deb、rpm 还是 AppImage：Ubuntu 梯子等发行版怎么选包

发布页上给 Linux 的文件通常有好几种格式，先按发行版排除。

| 格式 | 适用的发行版 | 特点 | 什么时候选 |
| --- | --- | --- | --- |
| .deb | Debian、Ubuntu 及其衍生版 | 由包管理器安装，处理依赖，有统一的卸载入口 | 这些发行版上的首选 |
| .rpm | Fedora、RHEL 系、openSUSE 等 | 同上，对应另一套包管理体系 | 这些发行版上的首选 |
| .AppImage | 不限发行版 | 单个文件，加上可执行权限即可运行，不写入系统目录 | 临时试用，或没有对应格式的包时 |
| .tar.gz、.gz | 不限发行版 | 压缩的可执行文件，内核多用这种形式 | 手动部署内核时 |

再按处理器架构选。在终端里运行下面的命令：

```bash
uname -m
```

输出 `x86_64` 对应文件名里的 amd64 或 x64；输出 `aarch64` 对应 arm64。树莓派这类 ARM 小主机和部分云服务器属于后者，下错了会提示无法执行。

Linux 梯子下载还有几处容易忽略的地方：

- **依赖**。图形客户端依赖系统里的网页渲染组件等库。用 deb 或 rpm 安装时包管理器会处理；用 AppImage 时，缺库需要你自己补。
- **发行版软件源与社区打包**。有的发行版社区会提供同名软件包，安装方便，但那是社区维护者打包的，不属于官方构建，来源和更新节奏需要自己判断。
- **内核的变体**。内核发布页上同一架构可能有多个变体，分别面向不同的处理器指令集或兼容性需求，含义以发布说明为准；拿不准就选说明里标为通用或兼容的那个。

## 桌面环境下的三个 Linux 特有问题

**系统代理不一定能自动设置。** 图形客户端的“系统代理”开关，本质是去改桌面环境的网络代理设置。主流桌面环境一般受支持；较小众的桌面环境或窗口管理器上，这个开关可能不起作用，需要你在浏览器里单独设置代理，或用环境变量。

**托盘图标可能不显示。** 部分桌面环境默认没有托盘区，客户端关掉窗口后就找不到入口，需要安装相应的托盘扩展。这不是客户端出了故障。

**TUN 模式需要额外权限。** 创建虚拟网卡属于特权操作。图形客户端通常会弹出系统的授权对话框，或要求先安装一个后台服务。授权窗口出现时，确认它是由你刚才的操作触发的。原理与适用场景见 [TUN 模式](/jiaocheng/tun-moshi/)。

## 服务器与无界面环境：内核加配置文件，交给 systemd 常驻

没有图形界面时，流程是“放好内核 → 准备配置 → 前台试跑 → 交给 systemd”。这里只讲思路，不给完整脚本。

1. **下载内核**。从 [Mihomo 内核官方发布页](https://github.com/MetaCubeX/mihomo/releases) 或 [sing-box 官方发布页](https://github.com/SagerNet/sing-box/releases) 下载对应架构的文件，解压后放到系统的可执行目录，并加上可执行权限。
2. **准备配置文件**。Mihomo 读取 YAML 配置，机场的 Clash 订阅下载下来就是这种格式；sing-box 读取 JSON 配置，机场不一定直接提供。配置文件里包含你的节点信息，权限设为只有运行它的用户可读。
3. **前台试跑**。先在终端里直接运行内核并指定配置目录，观察日志有没有报错、端口有没有监听成功。这一步通过了再做常驻。
4. **写 systemd 服务**。服务文件里要交代四件事：内核的路径和启动参数、配置目录、在网络就绪之后启动、异常退出后自动重启。两个项目的官方文档都给了示例，见 [Mihomo（Clash Meta）文档](https://wiki.metacubex.one/) 与 [sing-box 官方文档](https://sing-box.sagernet.org/)。
5. **启用并检查**。让服务开机自启，然后查看服务状态和日志，确认它在正常运行。

服务器上有两件事比桌面更要紧：

- **监听地址**。带公网 IP 的机器，如果让代理端口监听在所有网卡上，又没有防火墙限制，等于向整个互联网开放了一个代理。只给本机用，就让它只监听本地回环地址。
- **控制面板**。内核的外部控制接口可以用来切换节点、查看连接。同样不要暴露在公网上，并设置访问密钥。

订阅怎么自动更新、DNS 怎么配，分别涉及配置文件里的不同段落，可以先读 [Clash DNS](/jiaocheng/clash-dns/) 一文。

## 终端里的 Linux 代理：环境变量只对认它的程序生效

内核或客户端跑起来之后，终端里的命令并不会自动走代理。常见做法是设置环境变量：

```bash
export http_proxy=http://127.0.0.1:端口
export https_proxy=http://127.0.0.1:端口
```

端口填客户端设置页或配置文件里的混合端口、HTTP 端口，以你的实际配置为准。使用时记住三点：

1. 只在当前终端会话里有效。关掉窗口就没了，想长期生效要写进 shell 的配置文件。
2. 只对会读取这些变量的程序有效。curl、git、常见的包管理工具一般会读；有的程序有自己的代理设置项，要单独配。
3. 用 sudo 执行的命令、systemd 启动的服务、Docker 守护进程默认不继承这些变量。

git、npm、Docker 各自怎么配，见 [终端代理](/jiaocheng/zhongduan-daili/)；专门针对代码托管平台的思路见 [GitHub 梯子](/changjing/github/)。不想逐个程序设置时，改用 TUN 模式由系统层面接管。

## 怎么核对下载的是官方构建、代理确实在工作

**核对文件，三项：**

1. 地址是数据表里列出的官方仓库 releases 页，组织名与仓库名逐字符一致。
2. 发布页提供了校验值时，运行 `sha256sum 下载的文件名`，把输出与发布页上的值逐位比对。
3. 运行内核并查看它输出的版本信息，应当与数据表显示的版本一致。

**核对运行状态**，先看端口监听在哪个地址上：

```bash
ss -lntp
```

只想给本机用，监听地址应当是本地回环地址，而不是所有网卡。然后做两次请求对照：

- 设置环境变量后，用 curl 请求一个只有走代理才能访问的网站，看是否返回响应头；同时看内核日志里有没有出现这条连接，以及它命中了哪条规则。
- 再请求一个国内网站，日志里应当显示直连。两类请求都符合预期，分流才算正常。
