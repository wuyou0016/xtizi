免费节点的风险可以归成四类：来源不明、运营者能看到你的连接信息、极不稳定、与陌生人共用出口 IP 而容易触发账号风控。这四类问题有一个共同点：出了事没有人负责，你也没有办法自己验证对方。选梯子不提供任何免费节点，这篇只讲公开订阅背后实际会发生什么，以及怎么把损失压到最低。

## 免费节点从哪来：公开订阅和公益节点是怎么回事

先把说法对齐。平时说的免费节点，一般指有人把代理节点或订阅链接放到公开的地方，任何人拿到就能导入客户端使用。常见的叫法有三种：

- **免费订阅**：一条公开流传的订阅链接，导入客户端后会得到一批节点。
- **公益节点**：搭建者自称出于兴趣或互助、不收费地分享的节点。
- **试用或活动账号**：商业服务商限时、限量放出的体验账号。这一类有明确的运营方，性质与前两类不同，见[机场试用怎么找](/zhinan/jichang-shiyong/)。

最后一类不在本文范围内。本文说的免费节点，特指**来源和运营者说不清楚**的公开节点与订阅。

为什么到处都有？订阅链接本质上是一串能换到节点配置的网址，谁拿到谁就能用，复制转发几乎没有成本。另一方面，服务器和带宽是要花钱的。有人出于兴趣免费分享是可能的，但你没有办法确认眼前这一条是不是这样来的。“公益”两个字是对方自己的说法，不是你能核实的事实。

## 免费节点风险总览：四类问题对照表

下面这张表先给结论，后面逐类展开。

| 风险类别 | 实际会发生什么 | 怎么降低 |
| --- | --- | --- |
| 来源不明 | 节点可能由陌生人搭建，订阅也可能是别人泄露出来的；配置内容由对方决定 | 不当作日常线路，不登录重要账号，不与付费订阅混用 |
| 流量可被观察 | 运营者能看到你访问的域名、IP、流量和时间；明文页面的内容也可能被看到或改动 | 只访问 HTTPS 页面，不输入密码和支付信息，不安装任何证书 |
| 极不稳定 | 链接随时失效，节点突然全部超时，没有客服也没有退款 | 不把工作或需要持续在线的事情放在上面 |
| 共用出口 IP | 同一个 IP 被许多陌生人同时使用，目标网站可能频繁要求验证或限制访问 | 不在上面登录需要稳定环境的账号 |

前两类是安全问题，后两类看起来只是体验问题，但它们同样会连带影响你的账号，所以不能当成“只是慢一点”。

## 免费节点背后是谁：来源不明，没人说得清

用商业服务商时，至少有一个明确的运营主体：你知道向谁付款、向谁投诉、出问题能不能申请退款。免费节点这三样都没有。实际可能发生的情况有三种：

1. **节点本身就是为了观察使用者而架设的。** 这种可能性既无法排除，也无法证明，原因只有一个：你不知道对方是谁。只要对方运营着节点，就有能力记录经过它的连接信息。
2. **订阅是别人泄露出来的。** 订阅链接相当于一把免密钥匙，原理见[订阅链接泄露了怎么办](/bikeng/dingyue-xielou/)。付费用户把它发到公开的地方，就变成了“免费订阅”。你用的是别人买的流量，对方一旦发现并重置，这条订阅就立刻失效。
3. **配置内容由对方决定。** 订阅里不只有节点地址，导入后的配置还可能包含规则和 DNS 设置，部分客户端甚至支持在配置里加入脚本或覆写。来源不明的配置，等于把“哪些流量走哪里、域名怎么解析”的决定权交给了陌生人。

怎么降低：把来源不明的订阅当成不受信任的输入。不要把它和自己的付费订阅放进同一个配置，不要启用配置里你看不懂的脚本或覆写功能，用完就删除。

## 流量可被观察：免费节点的运营者看得到什么

原理和付费服务商一样。流量经过节点，节点就处在你和目标网站之间。访问 HTTPS 网站时，节点通常能看到目标域名或 IP、流量大小和时间，看不到加密后的页面内容和密码，细节可以看 [Mozilla MDN 对代理与隧道的说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Proxy_servers_and_tunneling)。完整的“能看到什么、看不到什么”见[梯子安全吗](/zhinan/tizi-anquan-ma/)。

那为什么免费节点的风险更大？差别不在技术能力，而在**有没有约束**：

| 对比项 | 有明确运营方的付费服务 | 来源不明的免费节点 |
| --- | --- | --- |
| 出了问题找谁 | 一般有主体、有工单、有条款 | 找不到人 |
| 隐私政策 | 可以读，可以对照条款追问 | 通常没有 |
| 记录会不会被滥用 | 取决于对方的承诺，同样无法外部验证 | 没有任何承诺，更无从验证 |
| 不信任它的代价 | 可以换一家 | 本来就没有信任的理由 |

除了“看”，免费节点还可能多出几件事：

- **明文 HTTP 页面。** 内容在节点上可见，也可能被改动，比如被插入额外内容。所以不要在地址栏不是 https 开头的页面里输入任何东西。
- **DNS 解析。** 如果域名解析交给了节点，对方可以返回错误的地址，把你引向假页面。HTTPS 站点会因为证书对不上，在浏览器里弹出警告。**看到证书警告就停下，不要选择继续访问。** DNS 是什么，可以读 [Cloudflare 的 What is DNS](https://www.cloudflare.com/learning/dns/what-is-dns/)。
- **根证书。** 任何要求你安装证书的免费节点或配套工具都不能接受。证书一旦被系统信任，对方就有机会读取原本加密的内容。

## 不稳定又共用 IP：用起来的两个直接后果

**第一个后果是不稳定。** 免费节点没有容量规划，往往是少数节点被大量人同时使用。链接被删除、节点被封、搭建者不再维护，都会让订阅突然失效。表现出来就是：导入成功但全部超时、今天能用明天没了、更新订阅一直失败。更新失败可以先对照[订阅更新失败怎么办](/paicha/dingyue-gengxin-shibai/)排除本机原因，但如果是免费订阅，原因多半出在源头。这是对成本结构的一般推断，选梯子没有也不提供任何免费节点的测速数据。

**第二个后果是共用出口 IP。** 一个出口 IP 同时被许多互不相识的人使用，只要其中有人做了批量请求、频繁登录之类会被目标网站视为异常的行为，这个 IP 的“信誉”就会下降。后果落在你身上：搜索时频繁出现验证页面，登录时被要求额外验证，个别服务直接拒绝访问。成因和处理思路见[谷歌一直要验证码怎么办](/paicha/google-yanzhengma/)，IP 类型的区别见[原生 IP、机房 IP 和住宅 IP](/zhinan/yuansheng-ip/)。

对账号的影响更值得警惕。账号在短时间内从相隔很远的几个地区登录，平台可能判断为异常并要求验证，严重时会临时限制账号。所以“只是登录一下”也不安全：风险不只在被偷看，也在账号被风控。降低的办法很简单，重要账号永远不要在免费节点的环境里登录。

## 拿到一条免费订阅，怎么自己核对

先说明：下面的做法只能帮你发现明显的问题，**核对通过不等于安全**，只代表没有发现异常。

1. **追溯来源。** 这条订阅是谁发的，有没有明确的说明页面，能不能联系到发布者。说不清来源的，到此为止。
2. **看链接开头。** 订阅地址以 https 开头更好。http 开头的订阅在传输过程中可以被中途改动，不建议导入。
3. **导入后先别连接。** 先在客户端里查看这份配置的内容，留意有没有你没添加过的 DNS 设置、脚本或覆写项目。具体入口随客户端和版本而不同，以当前版本为准，通用的导入方法可以参考[订阅链接怎么用](/jiaocheng/dingyue-daoru/)。
4. **使用独立的环境。** 新建一个没有登录任何账号的浏览器资料，或者用一台不放重要资料的设备测试。不要把自己的付费订阅也加进这个测试环境。
5. **观察连接列表。** 连接后，客户端的连接或日志页面一般能看到当前有哪些域名和 IP 经过代理。对照你实际打开的网站，如果出现大量你没有访问过的域名，先弄清是哪个软件在后台使用。
6. **检查系统证书。** 测试前后各看一次系统的证书管理界面，有没有多出不认识的证书。多了就移除，并停止使用这条订阅。

## 实在要用时的五条底线

如果你仍然决定短时间使用免费节点，下面五条是底线，不是建议：

1. **不登录任何重要账号。** 主邮箱、支付账号、网盘、工作账号、社交主号都不要登录。
2. **不输入支付信息、验证码和密码。** 也不要打开需要输入这些内容的页面。
3. **只访问 HTTPS 页面。** 遇到证书警告立即关闭，不选择继续访问。
4. **不安装证书，不运行配套的工具或脚本。**
5. **用完就关。** 不设开机自启，不长期开着全局模式，不与付费订阅混用。

这五条的作用，是把“万一对方有问题”的损失限制在没有价值的账号和访问上。重要的事情不要指望免费节点。请遵守所在地法律法规，选梯子不提供法律意见。
