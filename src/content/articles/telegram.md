Telegram 梯子的门槛很低：文字聊天耗不了多少流量，对节点地区也不挑，一条能稳定连上的便宜线路就够。需要花心思的是另外两件事：接入方式选哪种，是让 Telegram 跟着梯子客户端走，还是用它自带的代理设置；以及别让媒体自动下载把流量悄悄用掉。

## Telegram 对线路的要求：连得上、不断线，其余都不高

不管你习惯叫它电报梯子还是 TG 梯子，它对线路的要求都可以用一张表说完。

| 维度 | 要求程度 | 说明 |
| --- | --- | --- |
| 节点地区 | 低 | 基本不挑地区，选近的即可 |
| 出口 IP 类型 | 低 | 不需要为它追求特殊的 IP |
| 带宽 | 低 | 文字和图片用不了多少，传大文件时才有感觉 |
| 流量 | 文字低，媒体高 | 取决于自动下载设置和加入的群组数量 |
| 连接稳定性 | 高 | 即时通讯需要长时间保持连接，断线就收不到消息 |
| UDP 转发 | 通话时需要 | 语音和视频通话优先使用 UDP |
| 客户端后台存活 | 高 | 梯子客户端被系统关掉，通知就会延迟 |

可以看到，挑 Telegram 梯子时，花钱买高规格线路没有意义。值得关注的只有稳定性和后台存活，这两项和价格的关系不大，和客户端设置的关系更大。

顺带一提，注册和登录依靠手机号验证码，这一步由平台和短信通道决定，收不到验证码通常不是线路问题。

## 三种接入方式：跟随梯子客户端，还是用 Telegram 代理

Telegram 和多数应用不同，它在应用内自带代理设置，支持 SOCKS5 与 MTProto 两种代理类型。这一点在 Telegram 官方的[代理说明页](https://core.telegram.org/proxy)里有明确写明：所有手机和桌面客户端都可以通过代理连接，SOCKS5 只需要服务器地址和端口，MTProto 还需要一个密钥。加上跟随梯子客户端这条路，一共有三种接法。

| 接入方式 | 在哪里设置 | 适合谁 | 注意点 |
| --- | --- | --- | --- |
| 跟随梯子客户端（系统代理或 TUN） | 梯子客户端里 | 已经有机场、还要用其他应用的人 | 规则模式下要确认 Telegram 的流量走了代理 |
| 应用内 SOCKS5，指向梯子客户端的本地端口 | Telegram 的代理设置页 | 电脑端只想让 Telegram 走代理的人 | 地址填本机，端口以梯子客户端显示的为准 |
| 应用内 MTProto 代理 | Telegram 的代理设置页 | 没有梯子、只需要 Telegram 的临时情况 | 依赖代理提供者，来源不明时有风险 |

**第一种是默认选择。** 手机上的梯子客户端以 VPN 方式运行，会接管 Telegram 的流量，不需要在应用里再设置什么。电脑上如果只开了系统代理，Telegram 桌面端不一定跟随，这时可以改用 TUN，或者用第二种接法。两种模式的区别见[系统代理](/jiaocheng/xitong-daili/)和[TUN 模式](/jiaocheng/tun-moshi/)。

**第二种适合电脑端。** 在 Telegram 的设置里找到代理或连接类型的入口，添加一个 SOCKS5 代理，地址填 `127.0.0.1`，端口填梯子客户端的本地代理端口。这样只有 Telegram 走代理，其他程序不受影响。入口名称以当前版本为准。

**第三种不需要梯子客户端**，下一节单独讲。

用第一种接法时有一个特点要知道：Telegram 有相当一部分连接是直接连 IP 地址，而不是域名。只按域名写的分流规则可能匹配不到，流量就被当成直连，表现为一直显示连接中。主流规则集一般包含 Telegram 的 IP 段规则，如果你用的是自己写的规则，需要补上，写法见[分流规则](/jiaocheng/fenliu-guize/)。

## 公共 MTProto 代理：免费，但你不知道谁在运营

MTProto 是 Telegram 自己的通信协议，协议本身的说明见官方的[MTProto 页面](https://core.telegram.org/mtproto)，而 MTProto 代理怎么用，以前面提到的[代理说明页](https://core.telegram.org/proxy)为准。MTProto 代理是基于它的一种专用代理，任何人都可以搭建并把链接分享出来，点一下就能添加，所以流传很广。

它的好处是简单、不用装别的软件。但作为长期方案有几个问题。

- **你不知道运营者是谁。** 按协议设计，消息在客户端和 Telegram 服务器之间加密，代理转发的是加密后的数据。但运营者仍然能看到你的 IP 地址、连接时间和流量大小。
- **可能附带推广。** 代理提供者可以设置一个推广频道，显示在你的对话列表里。这是协议允许的功能，也说明提供代理的人通常有自己的目的。
- **没有人对稳定性负责。** 公共代理随时可能失效或被挤满，失效之后 Telegram 会卡在连接中，很多人因此误以为是梯子坏了。
- **只管 Telegram。** 其他应用和网站仍然打不开。

选梯子的建议是：把公共 MTProto 代理当作应急手段，不要当作日常方案；用完之后在代理设置页里把它关掉或删掉，避免它失效后拖住连接。来源不明的免费资源有哪些共性风险，见[免费节点](/bikeng/mianfei-jiedian-fengxian/)。

## 电报梯子的流量花在哪：自动下载是大头

纯文字聊天的流量可以忽略。真正消耗流量的是媒体，而且常常是在你没有点开的情况下发生的。

- **自动下载**。Telegram 可以按移动数据、Wi-Fi、漫游三种网络分别设置是否自动下载照片、视频和文件。
- **自动播放**。对话里的动图和视频会自动播放，播放就意味着下载。
- **大群和频道**。加入的群组和频道越多，自动下载的内容越多，哪怕你从不打开它们。

这里有一个容易忽略的错位：Telegram 认为 Wi-Fi 下的流量不值钱，默认在 Wi-Fi 下下载得更积极。但机场的流量不分 Wi-Fi 还是移动数据，只要经过节点就会扣。所以用梯子的人，应当把 Wi-Fi 下的自动下载也收紧。

建议的设置顺序：

1. 在数据与存储相关的设置里，关闭三种网络下的视频和文件自动下载，照片可以按需保留。
2. 关闭视频和动图的自动播放。
3. 不常看的大群和频道，归档或退出。
4. 用 Telegram 自带的流量统计观察一周，看哪一类占比高，再针对性调整。

流量莫名掉得快时，其他应用的后台流量也要一起排查，见[梯子流量消耗快](/paicha/liuliang-xiaohao-kuai/)。各类用途合计怎么估，见[梯子流量](/zhinan/tizi-liuliang/)。

## 通知延迟和语音通话：看后台存活与 UDP

**通知延迟。** 消息能不能及时提醒，取决于两件事：系统的推送通道是否通畅，以及 Telegram 与服务器之间的连接是否还在。后者依赖梯子客户端一直运行。手机系统为了省电，可能会把后台的梯子客户端停掉，连接一断，消息就要等你下次打开才出现。解决办法是在系统设置里允许梯子客户端后台运行、把它排除在电池优化之外，具体名称因手机品牌而异。

**语音和视频通话。** 通话会优先使用 UDP 传输。这带来两个限制：系统代理模式通常只接管网页类的流量，UDP 不一定经过代理；节点本身也不一定转发 UDP。文字正常而通话接不通时，先改用 TUN 模式，再换一个机场说明支持 UDP 的节点。选梯子没有各节点 UDP 表现的测试数据，这一项只能自己打一通电话来试。

## 自己验证：代理生效了没有、流量去哪了

1. **看连接状态。** 打开 Telegram，顶部长时间显示连接中或更新中，说明没有连上。应用内的代理设置页也会显示当前代理的连通情况，以当前版本为准。
2. **在梯子客户端里找它。** 打开客户端的连接列表，发一条消息，看有没有新增的连接，以及它走的是代理还是直连。走了直连，就是分流规则的问题。
3. **切全局模式对比。** 全局模式下能连上、规则模式下不行，同样指向规则。
4. **关掉梯子再看一眼。** 把梯子客户端关掉，Telegram 应当很快断开。如果它还连着，说明应用内另有一个代理在起作用，去代理设置页确认是不是之前添加的公共代理。
5. **看流量去向。** 在 Telegram 的数据与存储设置里查看流量统计，再对照梯子客户端里的已用流量。两边差距很大时，说明流量是其他应用用掉的。
6. **试一次通话。** 和朋友打一通语音，确认 UDP 这条路是否可用。

第 4 步经常被忽略，却很有用：它能分清你现在到底是靠梯子连上的，还是靠一个不知道谁运营的代理连上的。一直连不上时的逐项排查，在[Telegram 一直连接中](/paicha/telegram-lianjiezhong/)里。

## 下一步：便宜套餐够用，先月付试稳定性

Telegram 梯子不值得多花钱，把预算留给真正需要带宽和特定地区的用途。

- **只用 Telegram 和少量网页**：到[便宜机场推荐](/tuijian/pianyi/)里按月均价筛，选小流量、能月付的套餐。便宜不等于可以忽略稳定性，买完先挂几天观察掉线情况。
- **还要看视频或用 AI 工具**：按那些用途的要求去选，Telegram 不构成额外条件，从[机场推荐](/tuijian/)总榜开始看。
