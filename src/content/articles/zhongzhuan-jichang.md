中转机场，指的是流量先到一台境内的入口服务器，再由它转发到境外落地节点的机场方案。相对地，直连是你的设备直接连境外节点，专线则是把入口与落地之间那一段换成国际专用线路。三者的区别只在“中间那一段路”怎么走，而这一段路，恰恰是套餐页上最难核对的部分。

## 先看图：三种机场线路的数据路径

文字图示比一大段解释更清楚。箭头旁的括号是这一段路走的网络。

```
直连：你的设备 ──(运营商国际出口)──> 境外节点 ──> 目标网站

中转：你的设备 ──(境内线路)──> 境内入口 ──(公网隧道)──> 境外落地 ──> 目标网站

专线：你的设备 ──(境内线路)──> 境内入口 ══(国际专线)══> 境外落地 ──> 目标网站
```

三条路径里有几个固定不变的事实：

- 目标网站看到的永远是**落地节点**的出口 IP，不是入口服务器，也不是你自己的地址。
- 你的设备到入口、或到境外节点这一段，总是走公网和运营商网络，专线管不到。
- 入口和落地各有自己的带宽、负载和故障概率，路径上多一个节点，就多一个可能出问题的位置。

“落地”和“中转”这两个词，词典里有单独的条目：[落地节点](/cidian/luodi/)、[中转](/cidian/zhongzhuan/)、[直连](/cidian/zhilian/)。

## 直连机场和中转机场：多出来的一跳改变了什么

### 直连机场的取舍

直连的结构最简单：你的设备直接连到境外节点，中间没有额外服务器。

好处是故障点少。出了问题，要查的只有“你的网络”和“那一台节点”。代价是整条路径都要穿过运营商的国际出口，而国际出口在晚间用户集中的时段更容易拥挤。同时，节点的境外地址是固定对外暴露的，如果这个地址被网络侧限制，整个节点会直接失效。

### 中转带来了什么

中转在路径上插入了一个境内入口。它想解决两个问题：

1. **缩短“你到入口”这一段。** 入口放在境内机房，你连的是一个离你近、线路条件相对可控的地址。不少服务商会按电信、联通、移动分设入口，让不同运营商的用户连各自对应的入口。
2. **让对外暴露的地址变成入口。** 境外落地的地址不直接面对你，这是服务商常用的一种理由，但它不保证结果，入口地址同样可能被限制。

中转同时带来了新的问题：

- 入口成为单点，入口出故障，挂在它后面的节点会一起不可用。
- 入口到落地如果仍是公网隧道，拥堵只是从一段路搬到了另一段路。
- 流量要被入口和落地各经手一次，有些机场会为此设置不同的流量倍率，倍率问题见[流量倍率](/zhinan/liuliang-beilv/)。
- 多一跳意味着排查要多一层，慢的原因更难定位。

入口本身也有几种常见的实现形态，了解它们有助于看懂服务商的说明：

- **端口转发**：入口把收到的连接原样转交给落地，节点的密码、协议和加密设置都在落地一侧，入口只经手已经加密的数据。
- **隧道转发**：入口与落地之间先建立一条自己的隧道，再把用户的数据装进去传输，这一段的稳定性取决于隧道类型和底层链路。
- **负载均衡入口**：多台入口服务器分摊用户，单台入口出问题时可以自动切换，代价是服务商要多投入运维。

至于入口是不是只做转发，外部无法确认。选梯子的立场是：协议层已经加密，入口通常看不到你访问的内容，但这取决于服务商的实际实现，不应当把它当作可以验证的承诺。关于机场能看到什么，见[梯子安全吗](/zhinan/tizi-anquan-ma/)。

“中转机场”这个说法也有宽窄两种用法。窄义指入口到落地走公网的普通中转；宽义则把专线也算作中转的一种。看到宣传页时，先弄清对方用的是哪种含义。

## 专线和中转的区别：差在入口与落地之间

从结构上看，专线就是中转的一个升级版本：入口还在，落地还在，只是两者之间的链路换成了运营商提供的点对点国际专线。IPLC 和 IEPL 是这类专线最常见的两个名字，它们的区别在[IPLC 和 IEPL](/zhinan/iplc-iepl/)一文里单独拆解，这里只比较三种线路的差别。

| 对比项 | 直连 | 普通中转 | 专线（入口加国际专线） |
| --- | --- | --- | --- |
| 数据路径 | 你到境外节点 | 你到境内入口，再经公网到落地 | 你到境内入口，再经专线到落地 |
| 成本与价格 | 通常最低 | 通常居中 | 通常最高，专线本身的租用成本不低 |
| 晚高峰的一般规律 | 国际出口拥挤时更容易受影响 | 取决于入口到落地的公网段 | 专线段不经公网，但共享带宽被占满时仍会拥挤 |
| 地址被针对性限制的影响 | 境外节点地址直接暴露 | 暴露的是入口地址 | 暴露的是入口地址 |
| 故障点数量 | 较少 | 较多，多了入口 | 较多，多了入口和专线 |
| 排查难度 | 较低 | 中等 | 较高 |
| 常见宣传语 | 低价、节点多 | 线路优化、多入口 | 企业级专线、独享 |

表里是一般规律，不是承诺。几点必须提醒：

- “专线”不等于“不拥堵”。专线带宽是租来的，卖给多少用户、有没有超售，同样决定体验，见[超售与限速](/bikeng/chaoshou-xiansu/)。
- “专线”不等于“全程专线”。你到入口那一段永远是普通网络。
- “直连”不等于“更差”。路径简单、入口少，在不少网络环境下反而更稳定。
- 价格高低反映成本，不反映你个人的体验。

## 怎么自己判断节点是直连、中转还是专线

服务商的线路标签无法直接验证，但节点的大致结构，你可以用几条命令推断出来。

### 第一步：看节点地址解析到哪里

在客户端里找到节点的服务器地址，如果是域名，先解析出 IP。

```
nslookup 节点域名
tracert 节点域名        （Windows）
traceroute 节点域名     （macOS / Linux）
```

再把解析得到的 IP 放到任意一个能显示国家和所属网络的 IP 查询页里。

### 第二步：连上节点后，查询出口 IP

连上节点，用浏览器打开一个能显示当前出口 IP 的页面，记下它的国家和所属网络。

### 第三步：对照两个地址

| 节点服务器地址所在地 | 连上后的出口 IP 所在地 | 较可能的结构 |
| --- | --- | --- |
| 境外 | 与节点地址相同 | 直连 |
| 境内 | 境外，与节点地址不同 | 中转或专线 |
| 境外，但属于大型内容分发网络 | 视情况而定 | 节点经过了额外的前置层，不能直接判断 |

这套方法的局限要讲清楚：

- 它能分出“有没有境内入口”，分不出入口后面是公网还是专线。
- 部分节点使用前置代理或内容分发网络，地址解析结果不能直接当作服务器真实位置。
- traceroute 中间的跳数常因设备屏蔽探测而显示为空，缺行说明不了问题。

另一类不能自己验证的信息，是入口到落地之间的带宽有多大、有多少用户共用。这类问题只能通过服务商的说明和长时间的实际使用来判断，也可以在下单前直接问客服。

## 下单前可以向客服确认的六个问题

不要问“你们是不是专线”，这种问题得不到有信息量的回答。换成下面这些具体问题：

1. 入口是按电信、联通、移动分设的，还是统一入口？
2. 入口到落地之间走的是什么链路，是公网隧道还是运营商专线？
3. 入口出故障时，节点是否有备用入口自动切换？
4. 不同线路类型的流量倍率是否不同，倍率在哪里查看？
5. 线路出现长时间故障时，通知渠道是什么？
6. 同一类线路的节点，一般有多少用户共用？

对方能具体回答的，比一味强调“高端”“独享”的，更值得信任。回答含糊，说明这些信息要么不对外，要么对方也不清楚。

## 按使用场景选：如果你是……就……

- **如果你主要白天零散使用，预算有限**：直连或普通中转都可以先试，用最短周期验证，不必为专线多付钱。
- **如果你集中在晚上使用，或者断线会影响工作**：优先看中转的质量或专线档位，并为它准备一家备用机场，搭配思路见[备用机场](/zhinan/beiyong-jichang/)。
- **如果你多台设备分布在不同运营商网络下**：确认入口是否按运营商分设，再用各设备分别验证。
- **如果你最在意出口 IP 的类型**：线路类型不是主要因素，应当去看落地 IP 的属性，见[原生 IP](/zhinan/yuansheng-ip/)。
- **如果你已经遇到晚上变卡**：先别急着换线路类型，按[梯子晚上卡是为什么](/paicha/wan-gaofeng-ka/)定位慢在哪一段。

## 现在可以做的三步

1. **弄清自己要什么。** 回答两个问题：你主要在什么时段使用，断线几分钟对你意味着什么。答案决定是否需要多付线路的钱。
2. **用结构筛选。** 到[专线机场](/tuijian/zhuanxian/)看公开资料里标注了专线或中转的套餐，再按[机场怎么选](/zhinan/jichang-zenme-xuan/)里的参数逐项核对。
3. **买后立刻验证。** 用上一节的三步判断节点结构，并在晚间高峰时段，用你常用的服务实际使用一次。
